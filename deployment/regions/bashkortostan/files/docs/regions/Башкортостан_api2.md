# Дополнительный вход api2 для Башкортостана

Состояние на 12.09.2026. Адрес `https://api2-bashkortostan.delosud.ru`
создан по запросу владельца по схеме существующих шлюзов ХМАО и Урала.
Это дополнительный вход к тому же Worker и KV Башкортостана. Ключи владельца
и оператора прежние; ссылки с ключами хранятся вне Git в отдельных файлах
`owner-access-api2.txt` и `operator-access-api2.txt`.

## Устройство

- DNS: A → `195.19.66.234`, DNS only, TTL 300 секунд.
- VPS: отдельный `/etc/nginx/sites-available/delosud-gw-bashkortostan`,
  символьная ссылка в `sites-enabled`; [копия конфигурации](../../ops/vps-run/api2-bashkortostan.nginx.conf).
- Внешний HTTPS проксируется в `api-bashkortostan.delosud.ru`, с проверкой
  сертификата upstream, правильными Host/SNI и сохранением методов, тела,
  заголовков и query. Лимит nginx — 10 МиБ.
- Отдельный сертификат Let's Encrypt действует до 11.12.2026. Продление
  через существующий `certbot.timer`, webroot `/var/www/letsencrypt-bashkortostan`
  и hook `systemctl reload nginx`. HTTP перенаправляется на HTTPS;
  путь ACME остаётся доступным для продления.
- В access-log нового виртуального сервера записывается URI без query,
  чтобы не включать ключи ссылок в обычный журнал обращений.
- Конфигурация прежних шлюзов сохранилась побайтно. Их защищённые `/admin`
  после включения нового виртуального сервера отвечали штатным 401 без ключа.

Worker, расписание, данные и адреса автоматических исполнителей не менялись.
`api2` не добавлялся в автоматические fallback-адреса дашборда: это такой же
отдельный вход по ссылке, как существующие api2 ХМАО и Урала. Имя оператора
и его настройки интерфейса на новом origin нужно указать при первом входе;
серверная очередь и картотеки общие с основным адресом Башкортостана.

## Живые проверки

`nginx -t` прошёл, конфигурация применена через reload. DNS и действительный
HTTPS проверены с внешней машины. Владелец и оператор получают полноценный
HTML (около 358 КБ), содержащий ссылки на данные новой территории. Неверный
ключ получает 401, операторский `/admin/data` — 403. Журнал импорта и список
GitHub-запусков доступны с операторским ключом. CORS preflight возвращает 204
с разрешённым origin дашборда.

## Ограничение больших загрузок

Большой POST через api2 пока не работает. Безопасная проба использовала JSON
с пустым `court_domain` и 400 КиБ искусственного текста: Worker должен прочитать
тело и вернуть 400 до любых записей в KV или очередь. Через основной адрес
с Mac такой ответ получен; через api2 — 502. Тело 1 КиБ проходит, 32 КиБ уже
воспроизводит обрыв. Эти наблюдения не задают гарантированного рабочего лимита.

Сбой воспроизведён непосредственно с VPS, без nginx, с действующим ключом
в query: соединение с Cloudflare обрывается во время передачи тела.
Сетевые настройки ОС и прежних шлюзов не менялись. Точная причина внешнего
транспортного обрыва не установлена. Это ограничение нельзя считать
устранённым только по успешному входу в операторскую.

До устранения этого ограничения дампы загружаются через основной вход
`https://api-bashkortostan.delosud.ru/admin` с тем же ключом роли.
Доставка уведомлений и плановый парсинг используют прежние адреса.

При сопровождении менять только виртуальный сервер Башкортостана, проверять
`nginx -t` до reload. Не перевыпускать общий сертификат старых шлюзов:
у Башкортостана отдельные сертификат и renewal-конфигурация.
