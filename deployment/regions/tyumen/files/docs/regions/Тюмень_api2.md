# Дополнительный вход API2 для Тюмени

Состояние на 20.09.2026. Вход
`https://api2-tyumen.delosud.ru/admin` подключён через существующий VPS
к тому же Worker и KV Тюмени. Основной адрес —
`https://api-tyumen.delosud.ru/admin`. Ключи владельца и оператора общие
для двух входов; рабочие ссылки с ключами передаются владельцем вне Git.

## Устройство и выбор входа

- DNS: A → `195.19.66.234`, DNS only, TTL 300 секунд.
- Отдельный nginx vhost `/etc/nginx/sites-available/delosud-gw-tyumen`;
  [копия конфигурации](../../ops/vps-run/api2-tyumen.nginx.conf).
- Обычные HTTPS-запросы проксируются на `api-tyumen.delosud.ru` с правильными Host/SNI,
  проверкой upstream-сертификата и сохранением метода, тела, заголовков и query.
  Используются HTTP/1.1 и DNS resolver с `ipv6=off`. Лимит nginx — 10 МиБ.
- Отдельный сертификат Let's Encrypt действует до 19.12.2026.
  `certbot.timer` активен; для ACME используется
  `/var/www/letsencrypt-tyumen`. Остальные HTTP-запросы перенаправляются на HTTPS.
- В access-log записывается URI без query, чтобы ключи ссылок не попадали
  в обычный журнал обращений.

Пользователь выбирает API2 отдельной ссылкой. API2 не добавлен в
`PUSH_WORKER_FALLBACKS`: автоматические адреса дашборда, исполнителя и доставки
остались прежними. Имя оператора и настройки интерфейса на новом origin нужно
указать при первом входе; очередь и данные территории общие.

## Выполненные проверки

`nginx -t` прошёл. Прежние виртуальные серверы сохранены побайтно.
Владелец и оператор получают HTML с HTTP 200 и адресами `dashboard-tyumen`.
Без авторизации возвращается 401, операторский `/admin/data` возвращает 403.
CORS preflight даёт 204 и разрешает правильный origin дашборда.
Вход владельца и оператора и разграничение ролей проверены без VPN.

20.09.2026 в 15:22–15:24 (UTC+5) разовый запуск на VPS обработал три из трёх
реальных дампов очереди. Добавлены 23 дела: 22 из Тюменского областного суда
и одно кассационное; дамп Бердюжского суда не добавил новых дел. После обработки
очередь пуста, на GitHub Pages подтверждены 23 дела. Маршрут первичной загрузки
этих трёх дампов не проверялся: результат подтверждает обработку очереди
и публикацию, но не полный цикл загрузки через API2 без VPN. Описанное ниже
ограничение больших файлов сохраняется.

## Загрузка дампов

Для Тюмени включён отдельный сервис `court-monitor-upload-tyumen.service`
(`enabled`, `active`), слушающий только `127.0.0.1:8787`.
Nginx передаёт ему `/admin/import-dump` и `/_gateway-upload/`.
Сервис временно держит тело в памяти, а Worker забирает его обратным GET
с проверкой отдельного временного токена и SHA-256. Авторизация, проверка суда и очередь
остаются в Worker. В Worker опубликована настройка
`IMPORT_GATEWAY_ORIGIN="https://api2-tyumen.delosud.ru"`; код Worker не менялся.
В Cloudflare UI активна версия `96a0b954` (сокращённый ID).

Для обратного скачивания включены gzip и `proxy_buffering on`.
На этой конфигурации безопасные пробы с 1 КиБ, 400 КиБ и 2 МиБ повторяющегося
текста прошли за 1–1,5 секунды: Worker подтвердил точный SHA-256 и вернул
ожидаемый 400 на проверке пустого домена суда. Искусственные данные
в очередь не добавлялись. Это проверка передачи тела, а не реальный импорт.

Проба с 400 КиБ разнообразного текста, сжавшегося до 308 109 байт,
на этой же конфигурации завершилась 502 после 20-секундного таймаута Worker.
Ограничение внешней передачи крупных плохо сжимающихся дампов сохраняется.
Это не означает отказ для всех файлов такого исходного размера:
пробы с хорошо сжимающимся содержимым, включая 2 МиБ, прошли.

Локально прошли 17 тестов сервиса загрузки и 58 тестов механизма шлюза Worker.
Лимит nginx в 10 МиБ сам по себе не гарантирует прохождение каждого файла:
размер сжатого тела и состояние внешнего канала влияют на передачу.
Полный рабочий цикл без VPN на настоящей выдаче суда пока не подтверждён.

## Откат отдельного сервиса загрузки

1. Восстановить `/etc/nginx/sites-available/delosud-gw-tyumen` из сохранённой
   на VPS копии
   `/etc/nginx/sites-available/delosud-gw-tyumen.before-upload-20260920150645`.
   Это конфигурация обычного прокси без маршрутов в локальный сервис загрузки.
   Выполнить `nginx -t` и только при успешной проверке — `systemctl reload nginx`.
2. В Worker Тюмени установить `IMPORT_GATEWAY_ORIGIN=""` и опубликовать изменение.
   Сохранить пустое значение также в региональном `wrangler.toml`, чтобы
   следующий deploy не вернул отключённый маршрут.
3. Только после восстановления маршрутизации при необходимости выполнить
   `systemctl disable --now court-monitor-upload-tyumen.service`.
   Откат не требует менять другие виртуальные серверы, сертификаты или таймеры.

При сопровождении менять только виртуальный сервер Тюмени, выполнять
`nginx -t` перед reload и сохранять отдельный сертификат и конфигурацию
продления. Настройки других территорий не заменять.
