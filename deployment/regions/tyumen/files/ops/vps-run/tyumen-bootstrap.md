## Разделы областного суда

В конфигурацию Тюмени добавлен президиум областного суда: тот же домен
`oblsud--tum.sudrf.ru`, но отдельный кассационный раздел `delo_id=2800001`.
Апелляция остаётся в разделе `delo_id=5`. Всего подключены 26 судов и 27 разделов;
исходный реестр Excel из 26 строк сохранён без изменения происхождения записей.

С 22.09.2026 оба раздела имеют `search_gated=False` и `search_disabled=False`:
новые дела поступают из автоматического поиска. Свежая проверка с VPS разобрала
22 строки апелляции и 2 строки президиума без капчи. Ручные дампы остаются доступны
при `manual_import_all_courts=True`. Сохранённые дела президиума
проверяются штатным кассационным мониторингом по `cassation.link` и
`cassation.court_domain`: движение, заседания, результаты и доступные акты.
В обход входят дела текущей картотеки на стадии `cassation` с распознаваемой
ссылкой. Применяются общие правила отбора дел, повторов и пропуска уже проверенных
карточек; ответ с капчей или заглушкой не подтверждает успешное чтение.

Мониторинг карточек выполняется в утренние рабочие прогоны Тюмени (первый
плановый старт 06:10 UTC+5), а очередь новых дампов проверяется круглосуточно
каждые пять минут ежедневно. Изменение расписания импортов не переводит
полный парсинг на выходные и праздники.

Публичная конфигурация `RegionConfig.public_info()` сохраняется в блоке
`region` файла `data/cases.json`. Операторская читает его с опубликованного
сайта; для появления нового пункта нужно опубликовать актуальный
`presidium_courts` и обновить страницу админки.
Апелляция и президиум выбираются и учитываются раздельно, несмотря на общий
домен. Седьмой КСОЮ сохраняет собственный автоматический поиск.

## Дополнительный вход API2

20.09.2026 подключён `api2-tyumen.delosud.ru`: DNS A → `195.19.66.234`,
DNS only, TTL 300, отдельный nginx vhost `delosud-gw-tyumen` и сертификат
Let's Encrypt до 19.12.2026. `certbot.timer` активен, `nginx -t` прошёл;
прежние виртуальные серверы сохранены побайтно.

API2 проксирует запросы к существующему `api-tyumen.delosud.ru`; новые ключи,
Worker и данные не создаются. Вход владельца и оператора, разграничение ролей
и CORS проверены без VPN. Это отдельная ссылка, автоматические fallback-адреса
дашборда и исполнителей не менялись.

Отдельный сервис `court-monitor-upload-tyumen.service` включён и работает
на `127.0.0.1:8787`. В Worker через Cloudflare UI опубликовано
`IMPORT_GATEWAY_ORIGIN="https://api2-tyumen.delosud.ru"`. Обратная загрузка
использует gzip и буферизацию nginx. Пробы с 1 КиБ, 400 КиБ и 2 МиБ
повторяющегося текста дошли до ожидаемой валидации домена (400) с точным SHA-256;
данные в очередь не добавлялись. Это не гарантирует передачу каждого большого
файла: 400 КиБ разнообразного текста (308 109 байт после сжатия) на итоговой
конфигурации дали 502 по таймауту Worker через 20 секунд. Ограничение передачи
крупных плохо сжимающихся дампов сохраняется. Успешный вход в операторскую
не подтверждает полный рабочий цикл без VPN для всех файлов.
Локально прошли 17 тестов сервиса
и 58 тестов шлюза Worker. Подробности и порядок отката —
в [документе API2](../../docs/regions/Тюмень_api2.md).

## VPS и расписание

Вход `root` по ключу Mac работает. Deploy key `dashboard-tyumen@vps` сохранён
в GitHub с правом `Read/write`, fingerprint проверен. С VPS успешно выполнены
`git pull` и `git push --dry-run`; доступ к чтению и публикации подтверждён.

Настройка выбора `deploy_tyumen` ограничена новым клоном:

```sshconfig
Match host ssh.github.com exec "test $(pwd) = /opt/court-monitor/dashboard-tyumen"
  IdentityFile ~/.ssh/deploy_tyumen
  IdentitiesOnly yes
```

В `~/.config/court-monitor` подготовлены файлы с правами `0600`:

- `env.tyumen`: `REGION=tyumen`, собственный `DASHBOARD_URL`, `BANK_TRACK=1`
  и разрешённые параметры отбора из конфигурации Башкортостана;
- `worker.tyumen`: собственные `url=`, `owner_secret=`, `push_secret=`;
  файл читается как данные, не через `source`;
- `progress_token.tyumen`: отдельный токен прогресса Тюмени.

20.09.2026 путь `/opt/court-monitor/dashboard-tyumen` добавлен четвёртым
в `territories`. Прежние три территории сохранены; резервные копии списка
и SSH-конфигурации сохранены. Все четыре таймера `court-*` включены
и находятся в состоянии `active (waiting)`.

Общие окна после настройки 20.09.2026, время Екатеринбурга (UTC+5):

| Задача | Начало |
|---|---|
| Утренний парсинг | По будням с 06:00 |
| Опрос новых дампов и одиночных добавлений | Круглосуточно каждые пять минут, ежедневно |
| Проверка готовности доставки | По будням с 08:45 |
| Страховочные слоты импортов | Ежедневно 12:00/14:00/16:00/18:00/20:00 |

На VPS 20.09.2026 по согласованию с владельцем Тюмень и Башкортостан
объединены в один старт. Настройка
`/etc/systemd/system/court-parse.service.d/60-region-starts.conf` задаёт
`CM_PARALLEL_STAGGER_SECONDS=300` и
`CM_PARALLEL_START_DELAYS="sverdlovsk_yanao=0 hmao=300 bashkortostan=600 tyumen=600"`.
Задержки считаются от начала каждого общего утреннего слота:

| Территория | Первый старт по будням, UTC+5 |
|---|---|
| Урал: Свердловская область и ЯНАО | 06:00 |
| ХМАО | 06:05 |
| Башкортостан | 06:10 |
| Тюменская область | 06:10 |

Это план начала работы, а не подтверждение выполнения или срок завершения.
Территории работают с перекрытием. Общие повторные слоты — 06:30, 07:00,
07:30, 08:00, 08:30 и 08:45; пока предыдущая общая служба работает,
systemd не запускает её повторно. Успешно проверенные сегодня поиски и
карточки обычно пропускаются, недоступные дочитываются. После отметки
доставки дневного дайджеста повторный парсинг за день пропускается.
Парсер дополнительно учитывает российский производственный календарь;
будний таймер сам по себе не запускает обход в рабочую субботу.

Mac не включать вторым автоматическим исполнителем. Устройство общих служб —
в [VPS README](README.md).

С 20.09.2026 автоматический опрос новых дампов и одиночных добавлений
работает круглосуточно каждые пять минут, включая выходные и праздники.
Страховочные слоты импортов — ежедневно 12:00/14:00/16:00/18:00/20:00.
При неудачной попытке повтор выполняется в страховочный слот; занятый
парсингом регион ждёт освобождения общей блокировки.
Ранее в воскресенье 20.09.2026 три загруженных дампа ожидали буднего запуска
по прежнему расписанию и были обработаны разово по запросу владельца.

## Разовый импорт только Тюмени

Команда на VPS под `root` запускает штатный импортёр с общей блокировкой
клона, обработкой текущей очереди, публикацией данных и отчётами оператору:

```bash
systemd-run --unit="court-tyumen-import-manual-$(date +%Y%m%d%H%M%S)" \
  --property=Type=exec --property=User=root \
  --property=WorkingDirectory=/opt/court-monitor/dashboard-tyumen \
  /bin/bash -c 'source /opt/court-monitor/dashboard-tyumen/ops/vps-run/vps_env.sh; exec bash /opt/court-monitor/dashboard-tyumen/ops/mac-local-run/import_dumps.sh /opt/court-monitor/dashboard-tyumen --anywhere'
```

`User=root` задаётся явно: без него у transient-службы при первой пробе
не оказалось `HOME`, и скрипт завершился до чтения очереди. Команда не запускает
общие `court-import.service`/`court-delivery.service` и дайджест; штатный
импортёр может отправить служебный Telegram-алерт при ошибке.
Не добавлять `--force`: у импортёра такого флага нет.

Результат проверять по `ops/mac-local-run/import_dumps.log` в клоне
(строка «Готово: обработано N из M»), статусам и счётчикам заданий в операторской,
публикации картотеки на сайте. Одного кода выхода недостаточно: занятая
блокировка тоже приводит к штатному пропуску.

## Границы проверки

- Worker `GITHUB_PAT` не задан: недоступны связанные статусы Actions и ручной
  GitHub dispatch из админки. Автоматическое расписание VPS и replay после
  Git push от этого не зависят.
- Отдельный шлюз загрузки включён через `IMPORT_GATEWAY_ORIGIN`, но успешные
  синтетические пробы не подтверждают прохождение каждого большого файла:
  для крупного плохо сжимающегося дампа воспроизведён таймаут. Обработка трёх
  реальных заданий на VPS подтверждена; первичная загрузка через API2 — отдельно.
- Первый полный плановый прогон и фактическая доставка Telegram/Web Push
  ещё не проверены; разовый импорт их не запускал.
  Проверка авторизации не подтверждает генерацию модели или доставку уведомлений.
- Чтение карточек проверено в рамках трёх импортированных выдач. Это не
  подтверждает доступность всех остальных судов и всех карточек территории.
