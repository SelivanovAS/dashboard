Мониторинг гражданских дел ПАО Сбербанк: первая инстанция, апелляция,
кассация, судебные акты и заседания. Дашборд показывает картотеку и изменения,
а ежедневный дайджест и персональные push помогают следить за своими делами.
Есть основной трек исков против банка и отдельный трек «Иски банка».

**Дашборд ХМАО:** [открыть](https://selivanovas.github.io/dashboard/sberbank_dashboard.html).

Этот репозиторий — эталон общего кода и данные ХМАО. Урал (Свердловская область
и ЯНАО) и Башкортостан используют отдельные региональные копии. Реестры судов,
данные, Worker/KV, секреты и настройки браузера принадлежат своей территории.

Описание сверено с текущими файлами 13.09.2026. Состояние живых служб,
публикаций и секретов проверяется отдельно.

## Возможности

- Таблица и мобильные карточки, поиск и фильтры, подробная карточка дела,
  история инстанций и архивы.
- Ближайшие заседания, календарь по watchlist, время конкретного суда.
- Отслеживание дел, персональный Web Push, устанавливаемая PWA и офлайн-кэш.
- Программный дайджест событий с LLM-пересказами мотивировок актов.
- Операторская загрузка дампов и пачек дел, отдельная очередь со статусами
  и автоматическими повторами сетевых ошибок.
- Отчёты о чтении карточек и здоровье источников. Капча и заглушка не считаются
  успешным чтением; закрытые поиски пополняются через ручной импорт.

## Как работает обновление

1. VPS обходит суды каждой территории по утреннему расписанию. Порядок
   инстанций: кассация → апелляция → первая инстанция.
2. Отдельная служба обрабатывает полную очередь импортов. Каждый клон имеет
   свою блокировку `.run.lock`, общую для парсинга, импорта и доставки.
3. Данные публикуются в Git. С 08:45 по Екатеринбургу отдельная служба доставки
   повторно проверяет готовые выпуски, в том числе завершённый день без новых
   событий. Дневной гейт и журнал транзакций защищают от повторной доставки.
4. Маркер публикации запускает `replay_on_push.yml`: GitHub собирает дайджест,
   отправляет Telegram, публикует результат и отдельным шагом отправляет Web Push.
5. Приложение получает JSON с GitHub Pages. Подписки, календарь, роли и очередь
   обслуживает Cloudflare Worker.

Mac остаётся резервом и использует те же скрипты. В эталонном `wrangler.toml`
cron выключен (`crons = []`, `CRON_UTC = ""`), `IMPORT_EXECUTOR = "vps"`.
Ручной `update_cases.yml` сохранён для полного аварийного запуска.
Точные расписания и границы подтверждения Pages — в
[главе об эксплуатации](docs/technical/10-ci-cd-и-эксплуатация.md).

## Где лежит код

```text
dashboard/
├── app.js / styles.css / sberbank_dashboard.html   # интерфейс
├── service-worker.js / manifest.json              # PWA и кэш
├── data/                                         # картотеки, архивы, отчёты
├── scripts/update_cases.py                       # тонкий CLI-фасад
├── scripts/court_monitor/                        # Python-пакет
│   ├── regions/                                 # реестры и часовые пояса
│   ├── parsing/                                 # выдача, карточки, акты
│   ├── lifecycle.py / linking.py / storage.py    # стадии, связки, данные
│   ├── presidium_search.py                      # поиск открытых президиумов
│   └── digest/ / delivery.py / runs.py           # дайджест и конвейер
├── scripts/import_search_dump.py                 # импорт поисковых дампов
├── cloudflare-worker/                            # API, админка, шлюз импортов
├── ops/vps-run/                                  # systemd и Linux-обёртки
├── ops/mac-local-run/                            # общая реализация и резерв
├── .github/workflows/                            # replay, ручные запуски, CI
└── scripts/tests/ + tests/                       # проверки
```

Основная картотека хранится в `data/cases.json`; bank-трек — в
`data/cases_bank.json`, его события — отдельно. JSON является рабочим
источником данных, CSV сохранён для совместимости. Схема, архивы и правила
сохранения описаны в [модели данных](docs/technical/02-модель-данных.md).

## Локальный просмотр и проверки

Для просмотра без сборки запустите из корня репозитория:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте [локальный дашборд](http://127.0.0.1:8000/sberbank_dashboard.html).

Бэкенд использует Python; CI работает на Python 3.12. Зависимости проекта:

```bash
python3 -m pip install -r scripts/requirements.txt
python3 -m pip install pytest
python3 -m pytest
```

Объём проверок выбирается по изменению. Для документации:

```bash
python3 scripts/refresh_doc_anchors.py
python3 -m pytest scripts/tests/test_doc_anchors.py -q
git diff --check
```

`--json`, `--replay-last`, импорт и запуск workflow могут менять данные
и отправлять уведомления. `test_digest.yml` отправляет Telegram даже при
`commit_results=false`; это не обычный локальный тест.

## Настройки

Регион выбирается через env `REGION`, затем файл `REGION`, затем `hmao`.
Для Урала Python-код региона — `sverdlovsk_yanao`, браузерный namespace — `ural`.
Часовой пояс суда может отличаться от пояса территории: у 6-го КСОЮ в Самаре
UTC+4, у местных судов Башкортостана UTC+5.

Провайдеры LLM: Claude, GigaChat, OpenRouter. Python без env выбирает Claude;
`replay_on_push.yml` и `update_cases.yml` без Actions Variable выбирают
OpenRouter. Модель агента разработки не переключает LLM дашборда.

Переменные и секреты описаны в [эксплуатации](docs/technical/10-ci-cd-и-эксплуатация.md),
[LLM](docs/technical/06-дайджесты-и-llm.md) и
[Worker API](docs/technical/09-cloudflare-worker.md). Секреты не хранятся
в документации; при синхронизации сохраняются настройки каждой территории.
