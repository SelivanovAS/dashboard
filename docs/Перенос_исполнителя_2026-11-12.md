# Перенос исполнителя четырёх территорий

12 ноября 2026 года в 00:26 по Екатеринбургу исполнитель СберСуда переключён
с `195.19.66.234` на `152.228.114.30`. На подготовленном Mac доступен
`ssh sbersud-new`; для инструментов выпуска использовать этот SSH-алиас
и ключ `~/.ssh/id_ed25519`, а не прежний `delosud_gw`.

Четыре региональные программы, их паспорта, история Git, картотеки,
bank-events, очереди, кэши и отметки доставки перенесены без смены версий.
Общий источник разработки остаётся `codex/program`; региональные `main`
не переписывались. Mac LaunchAgents не включались, ЕРКНМ не переносился.

## Расположение и запуск

На новом сервере `/srv/projects/sbersud` — отдельный том 6 ГиБ. Каталоги
с привычными путями подключены через bind mounts из этого тома:

| Путь программы | Каталог на томе |
|---|---|
| `/opt/court-monitor` | `court-monitor` |
| `/root/.config/court-monitor` | `private/config` |
| `/var/lib/court-program-maintenance` | `state/court-program-maintenance` |
| `/var/lib/court-monitor` | `state/court-monitor` |

Имена клонов и порядок регионов сохранены: Урал, ХМАО, Башкортостан, Тюмень.
Для всех шести служб заданы `RequiresMountsFor` и проверка подключения тома.
Между территориями сохранены задержки 0/300/600/600 секунд. Расписания:

- парсинг: будни 06:00–08:30 каждые полчаса и 08:45;
- импорт: ежедневно 12:00–20:00 ежечасно и после парсинга;
- опрос новых импортов: ежедневно каждые 5 минут;
- доставка: будни 08:45–09:55 каждые 5 минут, 10:00–23:45 каждые 15 минут;
- дочитка: будни 12:00 и 16:00;
- сжатие истории без удаления версий: ежедневно 03:17.

`sbersud.slice` ограничивает совокупное потребление исполнителя: CPU 80%,
MemoryHigh 1152 МиБ, MemoryMax 1408 МиБ, MemorySwapMax 512 МиБ, TasksMax 256.
Это начальный бюджет, достаточность которого требует наблюдения обычных
обходов. Системный journald сохраняет подготовленные на новом сервере
ограничения 200 МБ, 14 дней; старые общесистемные настройки не переносились.

## Окружение и сеть

Единственный файл окружения служб — `/etc/sbersud-runtime.env`.
Существующие оболочки используют системный Python 3.12; `PYTHONPATH`
подключает подготовленные зависимости из `/opt/court-monitor-runtime/venv`.
`CM_PYTHON` также указывает на этот venv для использующих его запускателей.
Временные файлы и кэши направлены в том. Значения CA взяты из подготовленного
`/etc/sbersud-network-ca.env` и включены в общий файл окружения.

GitHub replay остаётся исполнителем пересказов и основной доставки Telegram.
Общий VPS-пролог ХМАО передаёт `CM_SUMMARY_GENERATION=0` дочерним запускам всех
территорий; отсутствие такой строки в отдельных региональных прологах
само по себе не означает включённую локальную генерацию.

Для прямых технических уведомлений VPS установлен локальный CONNECT-сервис
`sbersud-https-router.service` на `127.0.0.1:18130`. Telegram и OpenRouter
идут через подготовленный туннель `127.0.0.1:18129`; прочие адреса соединяются
напрямую. Домены судов РФ и GitHub также исключены из прокси через `NO_PROXY`.
Настройка действует в окружении служб СберСуда, не глобально. Расшифровки TLS
и записи URL, заголовков или содержимого запросов нет.

GitHub OCR ХМАО перенесён с прежним ограниченным SSH-пользователем,
ForceCommand, отдельным токеном и правилом tmpfiles. `OCR_SSH_HOST` указывает
на новый IP, `OCR_SSH_KNOWN_HOSTS` содержит доверенные ключи обоих серверов
для возможного возврата. Приватный ключ GitHub не заменялся.

Публичные шлюзы `api2-*.delosud.ru` остаются на старом сервере: они передают
загрузки в региональные Worker/KV и не пишут местную картотеку. Поэтому
старый сервер пока нельзя выключать. Workers, KV и DNS этих шлюзов не менялись.
Проблема внешнего TLS/443 нового сервера не решалась в рамках переноса;
панель доступна по `https://monitor.delosud.ru:8443`.

## Проверка выпусков после переноса

Координатор и узкий установщик допускают только один обязательный файл
`/etc/sbersud-runtime.env` с полным фиксированным набором значений.
Произвольные файлы, дополнительные переменные, иной прокси, пропущенный CA,
повторные свойства systemd, symlink/hardlink и небезопасные права отклоняются.
Хеш файла включён в снимок маршрутов координатора и повторно проверяется
внутри окна выпуска. Проверка не исполняет файл и не выводит его значения.
Прежняя установка без EnvironmentFile остаётся допустимой.

Для следующих выпусков нужен координатор из исходного коммита, включающего
эту поддержку. Старый координатор намеренно откажет новому окружению;
обходить его проверки или временно снимать настройки запуска нельзя.

## Резервная копия и возврат

На старом сервере сохранены исходная установка и закрытый архив
`/root/court-server-migration-20261112/backup.tar.gz`. Его копия, пофайловая
опись и результаты проверок находятся на новом сервере в
`/srv/projects/sbersud/migration/`. Проверены 4429 файлов и SHA-256 архива.
Это резервная копия проекта, не снимок всей виртуальной машины.

На старом сервере шесть таймеров выключены. Файл
`/var/lib/court-server-migration/fenced` запрещает запуск соответствующих
служб через дополнения `95-server-migration.conf`. Он не относится к
marker обычного координатора программных выпусков.

Для возврата сначала создать такой запрет на новом сервере, выключить его
шесть таймеров и дождаться завершения служб. Под штатными блокировками
вернуть на старый сервер актуальные данные и локальное состояние всех
четырёх регионов, если новый исполнитель уже их менял. Первоначальный архив
не должен заменять более свежую картотеку, историю Git или отметки доставки.
Затем вернуть `OCR_SSH_HOST` на старый IP. Только после подтверждения
отсутствия второго писателя снять запрет старого сервера и включить его
прежние таймеры. Принудительный запуск и тестовая рассылка не нужны.

## Наблюдаемые результаты

Контрольные суммы перенесённых файлов совпали; проверены паспорта четырёх
установок, целостность и связность Git, права публикации через dry-run,
авторизованный доступ к четырём пустым очередям. На новом сервере прочитано
по контрольной карточке каждого региона с совпадением номера и УИД.
Ограниченный OCR-канал проверен искусственным двусторонним обменом без модели;
доступ к техническому боту — методом getMe без сообщения.

Первый штатный опрос очередей нового сервера завершился 12.11.2026 в 00:30:16
с кодом 0. Утренний обход, настоящая капча через GitHub и штатная доставка
после переключения на момент этой проверки ещё не происходили. Полного
рабочего прогона, тестовых сообщений и платных модельных запросов для
проверки переноса не выполнялось.


## Исправление выпуска через bind mounts 12.11.2026

Первая установка программы после переноса выявила `EXDEV`: одинаковое устройство
`st_dev` у рабочих каталогов и журнала не гарантирует общий mount ID. Linux
запрещает атомарные rename/link между отдельными bind mounts даже одного тома.
Координатор теперь выбирает общий путь через `/proc/self/mountinfo`, сверяет
устройство, inode и mount ID каждого открытого каталога и выполняет прежнюю
атомарную операцию через проверенные дескрипторы. Канонические пути в журналах,
проверки владельца и поколения блокировок сохраняются; копирования вместо rename
и изменения подключений диска нет. Это относится и к блокировкам запуска,
и к служебной ссылке индекса Git и установке подготовленных файлов.

Для окна, оставшегося до первого разрешения публикации, предусмотрена явная
отмена новым закреплённым координатором:

```sh
python3 scripts/program_release.py recover --operation-dir <исходный-каталог> \
  --cancel-before-publish --coordinator-sha <полный-SHA-исправленного-координатора>
```

Исходные параметры, пакет координатора и журналы не заменяются. Дополнительный
исполнитель записывается отдельным неизменяемым документом; разрешены только
чтение состояния, отмена и завершение подтверждённой отмены. Наличие хотя бы
одного намерения публикации запрещает этот режим. Отмена всё равно проходит
обычные проверки служб, четырёх блокировок, программы, данных и удалённых веток.
После неё новый выпуск создаёт отдельное окно. Удалять marker или lock вручную
не требуется и не допускается.

Изолированная проверка Linux:
`scripts/tests/integration/program_maintenance_bind_mounts.py`. Она использует
временные папки и отдельное пространство подключений, воспроизводит `EXDEV`,
проверяет восстановление подготовленной блокировки и после обрыва публикации,
сохранность чужой блокировки, атомарную ссылку и замену файлов Git. Проверка не
запускает рабочие службы и не обращается к данным территорий.
