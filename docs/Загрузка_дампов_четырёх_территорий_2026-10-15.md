# Загрузка дампов четырёх территорий — 15.10.2026

## Маршруты и причина

Прямой большой POST из шлюза VPS в Cloudflare обрывался до ответа Worker.
В Башкортостане это подтверждено семью 502 в журнале nginx 15.10.2026.
В ХМАО и на Урале безопасная проба воспроизвела 502 через 15 секунд для JSON
150 032 байта; маленький JSON 32 байта проходил. Точная причина внешнего
сетевого обрыва не установлена.

Для дампов используется проверенная схема Тюмени: служба принимает JSON,
проверяет роль в существующем Worker, хранит тело в памяти и отправляет
короткое описание загрузки с отдельным токеном, размером и SHA-256. Worker
сам получает тело со шлюза, проверяет его и только затем ставит в очередь.
Nginx сжимает ответ обратного скачивания gzip. Повторного POST при обрыве нет.

| Регион | Вход | Служба | Локальный порт |
|---|---|---|---|
| ХМАО | api2-hmao.delosud.ru | court-monitor-upload-hmao | 8784 |
| Урал | api2-ural.delosud.ru | court-monitor-upload-ural | 8785 |
| Башкортостан | api2-bashkortostan.delosud.ru | court-monitor-upload-bashkortostan | 8786 |
| Тюмень | api2-tyumen.delosud.ru | court-monitor-upload-tyumen | 8787 |

В каждом Worker `IMPORT_GATEWAY_ORIGIN` указывает только на свой вход.
У ХМАО и Урала включение выполнено точечным PATCH настроек: байты опубликованного
кода Worker и остальные bindings проверены до/после и совпадают. Все старые
bindings переданы обратно с прежними типами и значениями; секреты сохраняются
по имени/типу без чтения их значений. Использован штатный API
[настроек Worker](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/script_and_version_settings/methods/edit/).

## Установка и региональная изоляция

Скрипты находятся в `/opt/court-monitor-upload-<территория>/`, units — в
`/etc/systemd/system/`. Службы слушают только loopback. Для ХМАО и Урала
подготовлены отдельные nginx-фрагменты `api2-hmao-upload.nginx.conf` и
`api2-ural-upload.nginx.conf` в профилях. Они устанавливаются в
`/etc/nginx/snippets/api2-<территория>-upload.conf` и включаются только в
соответствующий HTTPS server существующего `/etc/nginx/sites-available/delosud-gw`.
Фрагменты обслуживают ровно `/admin/import-dump` и `/_gateway-upload/`.

Перед включением сохранить исходный nginx, проверить код Python, unit через
`systemd-analyze verify` и всю конфигурацию `nginx -t`. Запустить службу до
reload nginx. После живой проверки включить автозапуск. Не заменять общий
сертификат ХМАО/Урала, не менять DNS, остальные пути, таймеры парсинга или
региональные рабочие Git-клоны. Конфигурации nginx Башкортостана и Тюмени
проверены побайтно и не менялись при включении ХМАО/Урала.

Все новые файлы включены в точные региональные профили общей программы.
Исправление инфраструктуры установлено вне региональных checkout; это не
новый пакет программы в региональном main. Подготовленный исходник и
обновлённые профили необходимо использовать при последующей штатной публикации,
иначе старый wrangler-конфиг не содержит включённого адреса шлюза.

## Проверки

- Интеграционный контракт каждой службы проверяет передачу больших тел,
  временный токен, SHA-256, авторизацию, очистку памяти, отсутствие повторного
  POST после неопределённого результата, запрет перенаправлений и OPTIONS.
- Общие тесты Worker проверяют прямой импорт при включённом шлюзе каждой
  территории и сохранение валидации суда, размера и содержимого.
- На четырёх публичных входах проба 150 032 байта и настоящая судебная HTML-
  страница возвращают ожидаемый 400 из-за намеренно пустого домена и правильный
  `X-Import-Gateway-SHA256`. Это проверяет целостность без фиктивной записи.
- Без ключа каждый вход отвечает 401; OPTIONS для разрешённого origin — 204.
- Контрольные реальные импорты используют только уже отслеживаемые дела,
  предварительно проверенные в dry-run: одна строка, `already=1`, без добавлений
  или дозаполнения. Для Тюмени выбрана открытая апелляционная выдача областного
  суда; страницы с капчей районных судов не отправлялись в очередь.

ожидаемый 400 означает сработавшую валидацию после полного получения тела.
HTTP 200 при настоящем приёме подтверждён отдельно результатом исполнителя.

## Границы и откат

Предыдущая проверка Башкортостана выявила таймаут на искусственном плохо
сжимаемом JSON 150 032 байта. Проверка обычных судебных HTML не гарантирует
передачу любого содержимого вплоть до формального лимита 10 МиБ. Ограничения
внешнего маршрута остаются; перед повторной отправкой смотреть журнал импорта.
Добавление нового дела и рассылки контрольные прогоны не проверяют.

Исходный nginx ХМАО/Урала и опись новых файлов сохранены на VPS:
`/opt/court-monitor-upload-audit/20261015/rollback/`. Для возврата восстановить
старый `delosud-gw`, проверить `nginx -t` и выполнить reload, затем отключить
новые службы. Адреса шлюзов в Worker можно удалить отдельным PATCH bindings,
сохраняя текущие остальные bindings; не восстанавливать старую версию кода.
Откат возвращает известный дефект прямых больших POST.

Ранее установленный шлюз Башкортостана имеет отдельный backup:
`/opt/court-monitor-upload-bashkortostan/backups/20261015-upload-fix/`.
