# Контекст для сессии: распил scripts/update_cases.py на пакет модулей

Написано 02.07.2026 сессией, которая делала П1–П2 (глубокое ревью + тесты +
самодиагностика). Прочитай целиком до первого действия — здесь границы
совместимости и ловушки, найденные при построчном ревью монолита.

## Зачем

`scripts/update_cases.py` — ~13 500 строк, 181 def/class. Каждая сессия,
трогающая любой кусок, платит токенами за навигацию по монолиту. Цель —
пакет модулей с тонким фасадом, чтобы будущие сессии (в т.ч. более слабые
модели) читали только нужный модуль. **Это характеризационный рефакторинг:
поведение не меняется вообще.** Никаких попутных улучшений, переименований
функций, «заодно почищу» — только перенос кода. Улучшения — отдельными
задачами после.

## Предусловия (уже выполнены)

- 228 тестов, все зелёные: `python3 -m pytest` из корня (конфиг [pytest.ini](../pytest.ini)).
- CI на каждый push: [.github/workflows/tests.yml](../.github/workflows/tests.yml).
- Алерт при падении ночного прогона (шаг `if: failure()` в update_cases.yml)
  и детектор молчаливой поломки парсеров — если рефакторинг что-то сломает
  в проде, юрист узнает утром из 🚨/🩺-сообщений, а не через неделю.
- Карта монолита — таблица «Ключевые точки» в [CLAUDE.md](../CLAUDE.md)
  (якоря строк актуальны на 02.07.2026).

## Жёсткая поверхность совместимости (ломать нельзя)

1. **Entrypoint**: GitHub Actions зовёт `python scripts/update_cases.py --json`.
   Флаги CLI (низ файла, `if __name__ == "__main__"`): `--json`,
   `--replay-last` (+`--push-all`), `--digest-only`, `--push-last-digest`
   (+`--owner-only`), `--backfill-appeal-anchors`, `--smart-skip`.
2. **Импортёры**:
   - `scripts/add_cases_manually.py` — импортирует 19 имён из `update_cases`,
     включая приватные (`_find_results_table`, `_parse_combined_cell`,
     `_CASE_ID_RE`, `_CASE_NUM_RE`, `_CASE_UID_RE`, `log`). Его импорты можно
     (и нужно) обновить на новые модули — это наш скрипт.
   - `tests/test_digest_render.py` и `scripts/tests/test_parsing.py` —
     `import update_cases as uc` (через `sys.path.insert(0, scripts)`).
   - `scripts/audit_watchlists.py`, `find_cassation_orphans.py` — НЕ
     импортируют монолит, не трогать.
3. **Env-переменные** читаются на уровне модуля при импорте
   (`ANTHROPIC_API_KEY`, `TELEGRAM_*`, `PUSH_*`, `DIGEST_FULL_LLM`,
   `LLM_PROVIDER`, `DIGESTED_ACTS_PATH`, `CASSATION_ACTS_PATH`,
   `PARSE_HEALTH_PATH`, …). Семантику «прочитано при импорте» сохранить.
4. **Данные и промпты**: поля cases.json, форматы файлов, тексты промптов
   (`GIGACHAT_SYSTEM_PROMPT`, промпт full-LLM, `_build_act_summary_prompt`)
   — не менять ни на символ (юрист их долго настраивал).
5. Соглашения проекта: код/комментарии по-русски, коммиты «EMOJI описание
   по-русски», без amend. Общение с юристом — по-русски.

## Главная ловушка: monkeypatch модульных атрибутов в тестах

Тесты патчат атрибуты **на модуле `uc`**, и константы, и функции:
`monkeypatch.setattr(uc, "JSON_ARCHIVE_PATH", …)`,
`setattr(uc, "CASSATION_ACTS_PATH", …)`, `patch.object(uc,
"_call_claude_simple", …)`, `patch.object(uc, "ACT_SUMMARIES_PATH", …)`,
`patch.object(uc, "DIGEST_FULL_LLM", False)`.

Если функцию перенести в подмодуль, а фасад просто ре-экспортирует объект,
патч фасада перестанет влиять на код (функция читает глобали СВОЕГО модуля).
Правильное решение: **переносить тесты вместе с кодом** — в том же коммите
переключать patch-цели на новый модуль (`from court_monitor import storage;
monkeypatch.setattr(storage, "JSON_ARCHIVE_PATH", …)`). Не городить
прокси-магию в фасаде. Правило самопроверки: если после шага тест зелёный,
но ты не менял его patch-цель, убедись, что он всё ещё тестирует то же самое
(патч попадает в модуль, где функция реально читает атрибут).

Следствие: **константу и функции, которые её читают, переносить в один
модуль в одном шаге** (пример: `JSON_ARCHIVE_PATH` + `cold_archive_path` +
`rotate_cold_archive`; `CASSATION_ACTS_PATH` + `load/save_cassation_acts` +
`link_cassation_cases`, который их зовёт, — через импорт модуля, не имени).

## Прочие ловушки

- `from __future__ import annotations` нужен в каждом новом модуле
  (локально у юриста Python 3.9, тайп-хинты `dict | None`).
- Глобальное состояние, живущее в одном экземпляре: `METRICS` (пишут
  `fetch_page` и `_warn_if_card_degraded`, читает блок 4e в `main_json`),
  `session` (requests.Session), `log` (logger «court-monitor»). Каждому —
  один дом; остальные импортируют модуль, а не копию имени.
- Кластер пост-обработки дайджеста (`_ensure_*`/`_validate_*`/`_drop_*`/
  `_normalize_*`, ~8191–9400) тесно связан с `generate_template_digest` и
  `polish_digest_html` — переносить одним куском.
- `pywebpush` импортируется лениво внутри `send_web_push` — так и оставить
  (зависимость опциональна).
- В `scripts/` уже есть `__init__.py` (пакетное имя для тестов) — не удалять.

## Рекомендованная структура пакета

## Порядок работы

Снизу вверх по зависимостям, один модуль = один коммит, после каждого:
`python3 -m pytest` зелёный + `python3 -c "import update_cases"` без ошибок.

1. Каркас: пустой пакет + фасад-ре-экспорт (ничего не переносится, тесты зелёные).
2. `config` → `courts` → `netutil` → `textutil` (листья без внутренних зависимостей).
3. `storage` → `health` → `parsing` → `lifecycle` → `linking`.
4. `digest` (самый большой, ~4 000 строк — можно в 2–3 коммита: llm/промпты,
   template+пост-обработка, диспетчер+full-LLM-контекст).
5. `delivery` → `runs` → финальный фасад (в `update_cases.py` остаются только
   импорты и argv-диспетчер).
6. Актуализировать таблицу «Ключевые точки» в CLAUDE.md (строки → модули)
   и раздел «Главные файлы»; обновить импорты `add_cases_manually.py`.

Работать прямо в `main` мелкими зелёными шагами (ночные автокоммиты бота
меняют только `data/*` — с кодом не конфликтуют, перед началом дня
`git pull --rebase`). Пушить пачку шагов за раз; каждый шаг — отдельный
коммит, откат = revert одного коммита. Если утренний прогон упадёт —
придёт 🚨-алерт: revert и ручной перезапуск основного workflow
(`update_cases.yml`, «📊 Основной прогон: парсинг + дайджест»).

## Проверка в конце (definition of done)

- `python3 -m pytest` — все зелёные, patch-цели тестов переехали на новые модули.
- `python3 scripts/update_cases.py --replay-last` локально без секретов:
  дайджест печатается в лог (Telegram не настроен — это ожидаемо), без трейсбеков.
- `wc -l scripts/update_cases.py` — фасад стал тонким (порядка сотен строк, не тысяч).
- `python3 scripts/add_cases_manually.py --help`-прогон невозможен (скрипт
  интерактивный) — достаточно `python3 -c "import add_cases_manually"` из scripts/.
- Push → CI зелёный → на следующее утро дайджест пришёл как обычно.
