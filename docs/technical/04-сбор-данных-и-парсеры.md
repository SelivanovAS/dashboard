# 04. Сбор данных и парсеры

## Что это и зачем

Это «глаза» системы — слой, который ходит на публичные сайты судов
(ГАС «Правосудие», `*.sudrf.ru`), скачивает страницы и превращает сырой HTML в
структурированные данные о делах. Никакого API у судов нет: данные приходится
выскребать из HTML-таблиц («скрейпинг»). Из-за этого парсеры — самая хрупкая
часть системы: меняется вёрстка сайта → ломается парсинг. Поэтому здесь много
защитных проверок и эмпирически подобранных констант, которые **нельзя менять
без проверки на живом сайте**.

Юристу важно понимать одно: всё, что показывает дашборд, добыто отсюда. Если
дело «пропало» или данные неполные — почти всегда причина в том, что суд
изменил карточку или временно недоступен.

## Как скрипт ходит на сайты судов

| Функция | Строка | Что делает |
|---------|--------|-----------|
| `polite_delay()` | [31](../../scripts/court_monitor/netutil.py#L31) | Случайная пауза `REQUEST_DELAY` = 2–3 сек между запросами, чтобы не нагружать суд и не попасть под блокировку. |
| `fetch_page(url)` | [36](../../scripts/court_monitor/netutil.py#L36) | Скачивает страницу. До `FETCH_MAX_RETRIES` (3) попыток с нарастающей паузой. **Декодирует из `windows-1251`** — сайты судов в этой кодировке, не UTF-8. Возвращает `""` при провале. |
| `parse_date(s)` | [15](../../scripts/court_monitor/textutil.py#L15) | Парсит судебный формат `ДД.ММ.ГГГГ` в `datetime`. |

HTTP-сессия (`requests.Session`) с браузерным `User-Agent` создаётся один раз
([строка 182](../../scripts/court_monitor/config.py#L182)). Счётчики запросов копятся в
`METRICS` для итоговой сводки прогона.

## `CourtConfig` — описание одного суда

[Строка 32](../../scripts/court_monitor/regions/base.py#L32). Dataclass, описывающий, как
обращаться к конкретному суду. Поля: `name`, `domain`, `delo_id`, `court_type`,
`srv_num`. Ключевое — `delo_id`, оно определяет тип производства и, как следствие,
имена таблиц и полей в URL:

| `delo_id` | Инстанция | `delo_table` | `name_field` | `&new=` |
|-----------|-----------|--------------|--------------|---------|
| `5` | Апелляция (Суд ХМАО-Югры) | `g2_case` | `G2_PARTS__NAMESS` | `5` |
| `1540005` | 1-я инстанция (гражд.) | `g1_case` | `G1_PARTS__NAMESS` | `0` |
| `2800001` | Кассация 7-го КСОЮ (гражд.) | `g33_case` | `G33_PARTS__NAMESS` | `2800001` |

Методы `search_url()` ([105](../../scripts/court_monitor/regions/base.py#L105)) и `card_url()`
([160](../../scripts/court_monitor/regions/base.py#L160)) собирают URL поиска и карточки. Поиск
ведётся по стороне дела — имя «Сбербанк» передаётся **закодированным в
windows-1251** (`SBER_NAME_WIN1251`), иначе сайт не найдёт совпадений.

Реестры судов: `APPEAL_COURT` ([36](../../scripts/court_monitor/courts.py#L36)),
`FIRST_INSTANCE_COURTS` (20 судов, [38](../../scripts/court_monitor/courts.py#L38)),
`CASSATION_COURT` ([40](../../scripts/court_monitor/courts.py#L40)).

> ⚠️ **Параметры 7kas подобраны эмпирически.** `delo_id=2800001`,
> `delo_table=g33_case`, `name_field=G33_PARTS__NAMESS`, `new=2800001` — это
> отдельная ветка для КСОЮ. Любое «логичное» значение (`new=0`, `new=5`,
> `ka1_case`) приводит к молчаливому «Данных по запросу не обнаружено». Менять
> только после ручной проверки на 7kas.

## `TableExtractor` — разбор HTML-таблиц

[Строка 13](../../scripts/court_monitor/parsing/tables.py#L13). Подкласс стандартного
`html.parser.HTMLParser`. Извлекает **все** `<table>` со страницы как списки
строк (списки ячеек). Особенности:

- **Поддержка вложенных таблиц** через стеки. Таблица регистрируется в момент
  открытия тега — это сохраняет порядок документа (внешняя раньше внутренней).
  Критично для вкладки «Обжалование»: внешняя таблица «ЖАЛОБА № N» (с видом
  жалобы — апелляционная/кассационная) должна попасть в список раньше вложенной
  «ДВИЖЕНИЕ ЖАЛОБЫ». Плоская версия теряла факт подачи жалобы.
- **Ссылки внутри ячеек** сохраняются через маркер `\x00HREF:`; достаются
  хелперами `cell_text()` ([81](../../scripts/court_monitor/parsing/tables.py#L81)) и
  `cell_href()` ([86](../../scripts/court_monitor/parsing/tables.py#L86)).

`extract_tables(html)` ([74](../../scripts/court_monitor/parsing/tables.py#L74)) — фасад.

## Парсеры поисковой выдачи

Поиск возвращает список дел; детали потом дочитываются из карточек.

### Апелляция — `parse_search_page`
[Строка 177](../../scripts/court_monitor/parsing/search.py#L177). Таблица результатов —
6-я на странице (индекс 5). Из объединённой ячейки «категория/стороны/суд»
данные выбирает `_parse_combined_cell` ([21](../../scripts/court_monitor/parsing/search.py#L21))
регулярками. Роль банка определяется по тому, в какой стороне найден один из
`SBER_PATTERNS`. **Дела, где «Сбербанк» — только дочка (страхование/НПФ/лизинг),
отсеиваются** (см. ниже).

### 1-я инстанция — `parse_first_instance_search`
[Строка 511](../../scripts/court_monitor/parsing/search.py#L511). Таблица результатов ищется
не по индексу, а по содержимому заголовка (`_find_results_table`,
[274](../../scripts/court_monitor/parsing/search.py#L274)) — у судов 1-й инстанции она на
другой позиции.

### Кассация — `parse_cassation_search_page`
[Строка 50](../../scripts/court_monitor/parsing/cassation.py#L50). Парсит выдачу 7kas. Главная
особенность — **HMAO-фильтр**: 7-й КСОЮ покрывает 8 регионов, нам нужны только
дела, чья 1-я инстанция — один из судов ХМАО. Сопоставление длинного имени суда
из карточки 7kas с нашим коротким делает `match_hmao_first_instance`
([106](../../scripts/court_monitor/courts.py#L106)) — с нормализацией ё→е и жёстким
guard'ом по маркеру региона (иначе «Октябрьский районный суд» матчится в
свердловский одноимённый). Пагинация не обходится — только первая страница.

## Фильтр «настоящего» Сбербанка

Поиск по слову «Сбербанк» цепляет и дочерние структуры. Их нужно отсеять, иначе
в мониторинг попадут чужие дела.

- `_SBER_SUBSIDIARY_PATTERNS` ([49](../../scripts/court_monitor/parsing/search.py#L49)) —
  регулярки дочек: «Сбербанк страхование [жизни]», «НПФ Сбербанк», «Сбербанк
  Управление Активами», «Сбербанк Лизинг» и т.п.
- `is_subsidiary_only_case(plaintiff, defendant)`
  ([64](../../scripts/court_monitor/parsing/search.py#L64)) — `True`, если «сбербанк» в
  сторонах встречается **только** в названии дочки. Такие дела пропускаются.
- `_is_real_sberbank(name)` ([84](../../scripts/court_monitor/parsing/search.py#L84)) и
  `determine_bank_role_from_participants(participants)`
  ([96](../../scripts/court_monitor/parsing/search.py#L96)) — пересчёт роли банка по списку
  участников из карточки (приоритет: Ответчик > Истец > Третье лицо). Если
  ПАО Сбербанка нет вовсе — для кассации это сигнал отбросить дело, для 1-й
  инстанции — поставить нейтральное «Третье лицо».

## Парсеры карточек

### Карточка 1-й инстанции / апелляции — `parse_case_card`
[Строка 260](../../scripts/court_monitor/parsing/cards.py#L260). Самая большая парсер-функция.
Из карточки извлекает: последнее событие и дату (вкладка «Движение дела»),
результат, статус, наличие и текст судебного акта, судью/докладчика, **УИД** и
«Номер дела в первой инстанции» (для связки инстанций), список участников
(для пересчёта роли). Отдельно — флаги движения по инстанциям из вкладки
«Обжалование решений»: подана апелляционная/кассационная жалоба, направлено в
вышестоящий суд, с массивами событий и датами. Эти флаги (`_fi_appeal_filed`,
`_fi_cassation_filed`, `_fi_sent_to_*` …) и питают машину состояний из
[03. Жизненный цикл](03-жизненный-цикл-дела.md).

`_warn_if_card_degraded` ([81](../../scripts/court_monitor/parsing/cards.py#L81)) ловит
ситуацию «карточка пришла обрезанной» (мало таблиц) — чтобы не затереть хорошие
данные пустыми.

### Карточка кассации — `parse_cassation_card`
[Строка 361](../../scripts/court_monitor/parsing/cassation.py#L361). Разбирает карточку 7kas.
Возвращает `None`, если нет блока «Рассмотрение в нижестоящем суде» (карточка
не та). Достаёт УИД, даты, категорию, судью, результат рассмотрения и его
влияние на акт апелляции, данные нижестоящего суда (через
`match_hmao_first_instance`), слушания, кассатора и его статус, участников, а
также **текст определения** из скрытого `<div id="cont_doc1">`.

### Текст актов
- `_extract_act_text(html)` ([30](../../scripts/court_monitor/parsing/cards.py#L30)) и
  `fetch_act_text(url)` ([970](../../scripts/court_monitor/parsing/cards.py#L970)) — для
  1-й инстанции/апелляции.
- `_extract_cassation_act_text(html)`
  ([153](../../scripts/court_monitor/parsing/cassation.py#L153)) — из `cont_doc1` на 7kas.

Текст акта нужен LLM, чтобы пересказать мотивировку
(см. [06. Дайджесты и LLM](06-дайджесты-и-llm.md)).

## Классификаторы исходов

Сырые формулировки судов нормализуются в фиксированные категории —
детерминированно, без LLM, чтобы исход было нельзя «нагаллюцинировать».

| Функция | Строка | Что классифицирует |
|---------|--------|--------------------|
| `classify_verdict(result, last_event)` | [1233](../../scripts/court_monitor/lifecycle.py#L1233) | Исход апелляции: оставлено / отменено / изменено и т.п. |
| `classify_verdict_fi(result)` | [1260](../../scripts/court_monitor/lifecycle.py#L1260) | Исход 1-й инстанции (удовлетворено/отказано/…). |
| `classify_cassation_outcome(result_text, result_for_appeal, review_result)` | [180](../../scripts/court_monitor/parsing/cassation.py#L180) | **Enum исхода кассации** (см. ниже). Управляет переходом `cassation → awaiting_relink`. |
| `cassation_remanded_to(result_for_appeal, act_text)` | [250](../../scripts/court_monitor/parsing/cassation.py#L250) | Куда направлено при отмене: `first_instance` / `appeal`. |
| `bank_side_outcome_fi(role, verdict)` | [1658](../../scripts/court_monitor/lifecycle.py#L1658) | Перевод исхода 1-й инст. в «для банка»: выигрыш/проигрыш/частично. |
| `bank_side_outcome(role, appellant, verdict)` | [1697](../../scripts/court_monitor/lifecycle.py#L1697) | То же для апелляции с учётом, кто апеллянт. |

### Enum исхода кассации

`classify_cassation_outcome` маппит поля карточки в одно из значений (русские
подписи — в `CASSATION_OUTCOME_RU`, [273](../../scripts/court_monitor/parsing/cassation.py#L273)):

| Enum | Подпись |
|------|---------|
| `cassation_dismissed_no_transfer` | 🚫 Отказ в передаче |
| `cassation_upheld` | Оставлено без изменения |
| `cassation_modified` | Изменено |
| `cassation_reversed` | Отменено |
| `cassation_remanded` | 🔁 Отменено и направлено на новое рассмотрение |
| `cassation_terminated` | 🛑 Прекращено / отозвано / возвращено |
| `cassation_other` | _(пусто — нестандартная формулировка)_ |
| `""` | _(карточка ещё в производстве)_ |

## Что делать при поломке парсера

- Сначала **открыть карточку дела на сайте суда вручную** и сравнить с тем, что
  ожидает парсер (индекс таблицы, заголовки колонок).
- Для 7kas — проверить, что поиск вообще что-то возвращает с текущими
  параметрами (см. предупреждение выше).
- Тесты парсеров — в [`scripts/tests/test_parsing.py`](../../scripts/tests/test_parsing.py)
  с зафиксированными HTML-`fixtures/`. Добавляя обработку нового кейса, кладите
  фикстуру и пишите тест (см. [10. CI/CD и эксплуатация](10-ci-cd-и-эксплуатация.md)).

Как все эти парсеры вызываются в правильном порядке за один прогон — в
[05. Конвейер обновления](05-конвейер-обновления.md).
