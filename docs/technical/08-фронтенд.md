# 08. Фронтенд (дашборд)

## Что это и зачем

Дашборд — это то, что юрист видит в браузере и в установленном приложении (PWA):
таблица всех дел с фильтрами, поиском, карточкой дела, аналитикой и блоком
последнего дайджеста. Это одностраничное приложение (SPA) **без фреймворков и без
сборки** — три файла: [`sberbank_dashboard.html`](../../sberbank_dashboard.html)
(тонкая оболочка), [`styles.css`](../../styles.css) (оформление) и
[`app.js`](../../app.js) (вся логика). Открывается прямо с GitHub Pages, данные
качает как статику — никакого бэкенда у дашборда нет (единственное серверное
взаимодействие — синхронизация подписок с Cloudflare Worker).

## Загрузка данных

Точка входа — `init()` ([app.js:1190](../../app.js#L1190)) → `loadFromSheet(url)`
([1333](../../app.js#L1333)). По умолчанию источник — `data/cases.json`
([`DEFAULT_SHEET_URL`, app.js:38](../../app.js#L38)).

- **JSON-режим** (основной): параллельно грузятся `cases.json` и
  `cases_archive.json` (`fetchJsonCases`, [1302](../../app.js#L1302)). Дела из
  архива, которых нет в активных, добавляются и помечаются `archived=true`.
  Холодные годовые архивы **не грузятся** (так задумано — см.
  [02. Модель данных](02-модель-данных.md)).
- **CSV-режим** (legacy-фолбэк): если URL ведёт на `.csv` или JSON недоступен —
  парсится CSV (`fetchCsvCases` + `parseCSV`).
- При полном провале показываются встроенные демо-данные (`DEMO_CSV`).

Каждое сырое дело приводится к внутренней модели:

- `jsonToCase(j)` ([747](../../app.js#L747)) — из объекта `cases.json`;
- `rowToCase(h, row)` ([610](../../app.js#L610)) — из строки CSV;
- `computeDerived(c)` ([689](../../app.js#L689)) — вычисляет производные поля
  (детальный статус, акценты, флаги архива). `computeDetailedStatus`
  ([394](../../app.js#L394)) определяет человекочитаемый статус («Основное СЗ»,
  «Отложено», «Без движения» и т.п.).

> ⚠️ Фронт держит **свою** копию `ARCHIVE_DAYS = 60`
> ([app.js:11](../../app.js#L11)). Её нужно синхронизировать вручную с
> `FI_ARCHIVE_DAYS` в бэкенде, иначе дашборд будет прятать дела не в такт с
> парсером.

## Фильтры, поиск, сортировка

`applyFilters()` ([2286](../../app.js#L2286)) — единая точка фильтрации. Над
поиском расположен верхний переключатель трёх областей:
`Основные | Иски банка | ★ Мои` (`renderDatasetSwitch`). Поиск и общий ряд
статусов (`Все / Новые / Сегодня / На неделе / Активные / Рассмотрено /
Архив`) одинаковы во всех областях и сохраняются при переключении.

Второй ряд контекстный, а его состояния раздельны:

- **Основные** — роль банка и инстанция (`filter-role`, `filter-stage`);
- **Иски банка** — контроль `Любой / С ИЛ / Ждут ИЛ / Обеспечение`
  (`filter-bank-control`);
- **Мои** — источник `Все / Основные / Иски банка`, своя роль и своя
  инстанция (`filter-mine-*`).

Скрытые значения другого раздела не участвуют в `applyFilters`; при возврате
они восстанавливаются. «Сбросить» очищает общий статус и только контекст
текущего раздела.

**Фильтр «Суд» (v172)** — выпадающий список последней группой второго ряда,
общий для всех трёх разделов. Источник истины — скрытый `#filter-court`,
опции наполняет `populateFilterOptions` из активного датасета: только суды,
по которым есть дела, со счётчиком, по алфавиту коротких имён (весь реестр
`REGION_INFO.fi_courts` не выводится — на Урале это дало бы десятки пустых
пунктов). Видимые копии (ряд сегментов + мобильная шторка) рисует
`renderChipBar` **без id** — иначе один HTML в двух местах дал бы дубль id.
Семантика — суд **1-й инстанции** дела (`courtFilterKey`,
[136](../../app.js#L136)): «дела моего суда» не должны уезжать из фильтра при
апелляции. Ключ — нормализованное ИМЯ суда (ё→е, пробелы, регистр), НЕ
`court_domain|srv_num`: `srv_num` в данных у одного суда записан то числом,
то null (Сургутский городской раскалывался бы на два пункта), фолбэк null→1
сливает районный суд и Покачи на общем домене, а у дел, заведённых с выдачи
апелляции, домена нет вовсе. Персиста нет — выбор живёт до перезагрузки, как
остальные фильтры; «Сбросить» снимает его в любом разделе. Догрузка
bank-архива/списка освежает опции перед пересчётом (суд, живущий только в
архиве, попадает в список). Стражи —
[test_frontend_court_filter.py](../../scripts/tests/test_frontend_court_filter.py).

Полнотекстовый поиск (`onSearchInput`, [2057](../../app.js#L2057))
глобальный: сначала выводит результат текущего раздела с его фильтрами, затем
остальные группы без дублей в порядке `Мои → Основные → Иски банка`.
Сортировка (`toggleSort`) применяется к первой, текущей группе.

## Подписки на дела (watchlist)

Юрист помечает дело звёздочкой ★. Это хранится локально и синхронизируется с
сервером (Worker → KV), чтобы push приходили персонально.

На телефоне круглая ★ рядом с поиском дублирует верхний раздел «Мои» и
показывается только при непустом watchlist. Верхняя капсула отвечает за
структуру экрана, нижняя — за быстрый вход в подписки во время прокрутки
карточек. После снятия последней подписки нижняя звезда скрывается, а верхний
раздел «Мои» остаётся доступен с пустым состоянием.

- Ключ хранения — `localStorage['watchlist_v1']` (`WATCHLIST_KEY`,
  [4833](../../app.js#L4833)). Звезда переключается `toggleWatch`
  ([5158](../../app.js#L5158)).
- **Синхронизация на Worker**: `scheduleWatchlistSync` ([5238](../../app.js#L5238))
  дебаунсит серию кликов (600 мс) в один `POST /watchlist`
  (`syncWatchlistToWorker`, [5246](../../app.js#L5246)). Worker канонизирует
  присланные алиасы в FI-ID и возвращает канон — фронт принимает серверную
  версию.
- **Reconcile после `/subscribe`**: `reconcileWatchlistWithServer`
  ([6276](../../app.js#L6276)) сводит локальный и серверный списки (например,
  при переустановке PWA берёт список с сервера).
- **Алиасы**: одно дело имеет несколько номеров (скобочный двойник, апел.
  `33-…`, касс. `8Г-…`, материал `М-…`). С v98 watchlist хранит ТОЛЬКО
  канонический bare-id, а любой видимый номер сводится к нему через
  `canonCaseNumber` ([5087](../../app.js#L5087)) по карте, которую строит
  `buildWatchCanonMap` ([5024](../../app.js#L5024), зеркало
  `wnBuildAliasToCanonical` из worker.js). Поэтому звезда переживает смену
  номера при переходе стадии, а отписка удаляет ровно ту запись, по которой
  идёт push.

### Синхронизация подписок между устройствами (профили, 26.08.2026)

Устройства юриста связываются коротким цифровым кодом в профиль
`profile:<uuid>` в KV Worker'а: watchlist общий, снятие звезды зеркалится.
Полное описание модели (KV-схема, LWW, совместимость) — CLAUDE.md, раздел
«Синхронизация подписок между устройствами»; здесь — фронтовая сторона.

- Связка устройства — `lsKey('profile_id')` + `profile_base_ts` (последний
  увиденный LWW-штамп) + `profile_dirty` (недопушенные правки).
- `syncWatchlistToWorker` — диспетчер: при связке уходит в
  `syncWatchlistToProfile` ([5355](../../app.js#L5355)) — **без push-гардов**,
  синк работает и при запрещённых уведомлениях; иначе прежний
  endpoint-путь (`syncWatchlistToWorkerLegacy`). 409 от Worker'а → накат
  тоглов текущей сессии (`profileSessionOps`) поверх серверного набора и
  ровно один повтор. На старте профиль тянет `loadProfileWatchlist`
  ([5445](../../app.js#L5445)).
- UI — раздел «Синхронизация устройств» в шторке ⚙ «Настройки»
  (`renderSettingsSheet`; с 03.09.2026, до того — кнопка 🔗 в шапке) → кнопка
  открывает окно «Синхронизация подписок» (`renderSyncSheet`,
  [5772](../../app.js#L5772)): на мобиле bottom-sheet, на ≥769px — мини-окно
  по центру (общее CSS-переопределение `#sync-sheet`/`#whatsnew-sheet`/
  `#settings-sheet`). В той же шторке настроек — push-уведомления
  (`setPushUiState`, бывший колокольчик шапки), календарный фид
  (`calFeedBlockHtml`: «Скачать файл (.ics)» — путь для корпоративного OWA,
  где подписка по ссылке невозможна) и «О приложении».
- QR кодирует deep-link `?pair=<код>` (генератор — vendored `qrcode-gen.js`),
  на втором устройстве его обрабатывает `maybeHandlePairParam`
  ([5853](../../app.js#L5853)). Для iOS-PWA (хранилище отдельно от Safari)
  — сканер внутри приложения: `startSyncScan` ([5936](../../app.js#L5936)),
  getUserMedia + ленивый vendored `jsqr.js`.

### Раздел «★ Мои»

Это третий равноправный раздел, а не быстрый фильтр. Он видим всегда, в том
числе при нуле звёзд; пустой раздел объясняет, как добавить дело. Набор строго
равен watchlist обеих картотек: новые дела без звезды не подмешиваются.
При глобальном поиске эта строгая выборка остаётся первой группой, после неё
могут появиться совпадения из «Основных» и «Исков банка». Для composite-звёзд автоматически подгружаются
активный список и горячий архив банка. Состояние выбранного раздела —
`localStorage['filter_mine_v1']` (`FILTER_MINE_KEY`). Снятие последней звезды
не выбрасывает пользователя в «Основные» — остаётся empty-state.

## Блок «Дайджест» и режим «Мои» (`?mine=1`)

В дашборде есть свёртываемый блок последнего дайджеста (читает `last_digest.json`).
У него два вида (`_digestViewMode`, [app.js:6689](../../app.js#L6689)):

- **«Общий»** — полный текст дайджеста для всех.
- **«Мой»** — только события по делам из watchlist.

Переключатель «Общий ⇄ Мой» в шапке блока (`setDigestView`). Начальное значение
задаёт URL `?mine=1` — именно его кладёт `click_url` персонального push
(см. [07. Доставка и уведомления](07-доставка-и-уведомления.md)). В mine-режиме
фронт читает `last_digest_context.json` и фильтрует события клиентским аналогом
`_filter_events_by_watchlist`. Набор строгий: секции новых дел тоже проходят
проверку watchlist. HTML дайджеста
перед вставкой проходит `sanitizeDigestHtml` ([6734](../../app.js#L6734)) —
оставляет только безопасные теги и чистит `href` от `javascript:`.

## Счётчик посещений (31.08.2026)

Единственный запрос, который фронт делает к Worker'у на КАЖДОМ визите —
`pingVisit()` ([4804](../../app.js#L4804)). До него обычное открытие дашборда
не оставляло следа нигде: `/subscribe` летит только у уже существующей
push-подписки, `/profile/get` — только при связке устройств, данные грузятся с
Pages мимо Worker'а.

- Тело — ровно два поля: `{v, own}`. `v` — случайный UUID браузера из
  `lsKey('visit_id')` (`getVisitId`, [4786](../../app.js#L4786)); `own` — булев
  флаг «это устройство владельца», выведенный из наличия `owner_secret`. Сам
  секрет на публичный роут не уходит. Счёт анонимный: ни `profile_id`, ни
  endpoint подписки, ни имени.
- `Content-Type: text/plain` — CORS-safelisted значение, браузер не шлёт
  preflight `OPTIONS`, и визит стоит один запрос вместо двух.
- Клиентский гейт `VISIT_PING_GAP_MS` = 30 минут; штамп ставится ДО запроса —
  с лежащим Worker'ом иначе уходил бы пинг на каждую перезагрузку страницы.
- Ранние выходы: пустой `WORKER_HOSTS` (территория без Worker'а) и
  `!navigator.onLine` (офлайн-PWA). Всё тело в `try/catch`: упавший счётчик не
  должен ни ломать дашборд, ни сорить в консоль.
- Точек вызова две: старт страницы и `visibilitychange` — установленный PWA
  живёт открытым сутками, и без второй следующий день не засчитался бы вовсе.
- Service worker пропускает всё, кроме GET, поэтому POST-пинг идёт мимо кэша.

Схема хранения, потолок записей и сводка для админки —
[09-cloudflare-worker.md](09-cloudflare-worker.md), раздел «Счётчик посещений».

### Офлайн: разведённые жизненные циклы кэшей (v170)

Жалоба юриста 15.08.2026: без сети PWA долго висел белым экраном, затем
показывал 4 демо-дела вместо сохранённых. Три независимых дефекта.

**1. Данные стирались при каждом обновлении приложения.** `data/*.json`
лежали в версионированном `CACHE_NAME`, а правка фронта = обязательный бамп
`CACHE_VERSION` (39 за 30 дней перед правкой) — `activate` сносил их вместе
с кодом. Теперь **два кэша с разными жизненными циклами**:

| Кэш | Версионируется | Что внутри |
|---|---|---|
| `sber-jurist-<ns>-<vN>` | да | код, разметка, шрифты, иконки |
| `sber-jurist-<ns>-data` | **нет** | `data/*.json` — переживают деплой |

⚠️ Имя data-кэша обязано НЕ оканчиваться на `-v<цифры>`: ровно это спасает
его от предиката `ownVersion` в `activate` (он же защищает кэши соседней
территории — ХМАО и Урал живут на одном origin github.io). `migrateDataCache`
переносит данные из приговорённых кэшей **до** их удаления; гарды — свой
origin, свой `SCOPE_PATH` (легаси-кэши до v107 общие на весь origin), не
перетирать более свежее, сбой одной записи не роняет миграцию. При обрыве SW
посреди `activate` старые кэши просто останутся до следующего бампа — данные
не теряются ни в одной точке.

**2. Ни одной операции с дедлайном.** При «сеть есть, интернета нет» `fetch`
не падает, а висит до таймаута ОС. Введён `withDeadline` — **гонка промисов,
не `AbortController`**: `fetch(request,{signal})` пересобирает `Request`, и у
навигации `mode:'navigate'` схлопывается в `same-origin`, ломая редиректы;
проигравший гонку ответ дотекает в кэш под `waitUntil`. Навигация 3.5 с,
`last_digest.json` 4 с, статика 8 с, данные 25 с (страховка: страница режет
свои запросы раньше — `FETCH_TIMEOUT_MS`).

Google Fonts подключались render-blocking `<link>` и при непрогретом кэше
держали белый экран: defer-скрипты не исполняются, пока висит стилевой лист.
Шрифты переехали в репозиторий (`fonts/*.woff2`, вариативные — один файл на
все начертания 400-700, ~110 КБ, в `APP_SHELL`); IBM Plex **Mono** выброшен —
его единственным потребителем был `.setup-body code` невидимого экрана
настройки. `#loading-screen` виден с первого кадра, а инлайновый
`__bootWatchdog` (12 с) показывает «нет связи», если `app.js` не доехал вовсе.

**3. Демо-дела вместо честной ошибки.** `loadFromSheet` на любую ошибку
подставлял `DEMO_CSV`: из 8 демо-дел 4 старше `ARCHIVE_DAYS` и скрыты
фильтром «all» — отсюда ровно 4 чужие карточки. Теперь окно само читает Cache
Storage (`readJsonFromCache` внутри `fetchJsonCases` — страховка от
синтетического 503 SW и от «SW ещё не контролирует страницу»); при пустом
кэше — экран `#nodata-screen` с «Повторить», демо осталось по явной ссылке.
Снимок из кэша подписан меткой «офлайн» рядом с «Данные от: …».

Прочие рубежи: `cache.put` живёт **только** в `cachePutSafe` (отказ по квоте
превращал валидный 200 в 503 → демо-дела); сигнал `data-updated` шлётся лишь
при успешной записи; `ignoreSearch`-фолбэк в `cacheFirst` (`APP_SHELL` хранит

### Свежесть данных: SWR + сигнал о новом снимке (v127)

`data/*.json` идут по **stale-while-revalidate**: кэш отдаётся мгновенно,
сеть обновляет его в фоне. Network-first тут не годится — `cases.json` ~2 МБ,
`cases_bank.json` ~1.4 МБ, первый экран ждал бы сеть. Но у SWR есть цена:
страница показывает снимок **предыдущего** прогона, а свежий виден только со
следующего открытия. `fetch(url,{cache:'no-cache'})` в `fetchWithTimeout` от
этого не спасает — это директива HTTP-кэша, service worker её не касается.

Инцидент 03.08.2026: юрист открыл дашборд после утреннего прогона и увидел
дело 2-592/2025 активным, хотя тот же прогон увёл его в архив трека. Блок
дайджеста рядом был уже сегодняшний (`last_digest.json` — network-first), а
шапка писала «Обновлено: <текущее время>» — время РЕНДЕРА страницы, так что
отличить вчерашний снимок было нечем.

Как работает сейчас:

1. `staleWhileRevalidate` сравнивает `ETag` (на GitHub Pages он есть; фолбэк
   `Last-Modified`) кэшированного и сетевого ответа. Отличается И кэш был
   непуст → после `cache.put` шлём окнам `postMessage({type:'data-updated'})`.
   Первая загрузка сигнала не даёт — там и так свежие данные.
2. `onDataUpdated` в app.js складывает затронутые датасеты (`dataFileKind`:
   main / bank) и через 1,5 с дебаунса зовёт `applyPendingDataRefresh` —
   `loadFromSheet(url,{quiet:true})` и/или `reloadBankDataset()`. Повторный
   fetch попадает в уже свежий кэш: мгновенно и без сети. Экран загрузки не
   мигает (`quiet`), проход ТИХИЙ — тост «Данные обновлены» убран 03.09.2026
   (решение юриста: с автообновлением при возврате во вкладку он срабатывал
   на каждый утренний заход и двоился по файлам, докачавшимся позже
   дебаунса); свежесть видна по штампу «Данные от: …» в шапке. Пока проход
   в полёте (`_dataRefreshInFlight`), новые сигналы копятся и дочитываются
   одним хвостовым проходом — параллельных `loadFromSheet` нет.
3. Пока открыт drawer, шторка фильтров или beacon дайджеста (`uiBusyForRefresh`),
   перерисовка откладывается — набор не теряется, `closeDrawer` /
   `closeFiltersSheet` / `closeDigestBeacon` зовут проход снова.
4. Шапка (`renderMeta`) показывает «Данные от: …» — `updated_at` файла, а не
   время рендера. `parseIsoUtc` дочитывает «Z» к naive-ISO: Python на
   UTC-раннере пишет штамп без него, и браузер принял бы UTC за локальное
   время (ХМАО = UTC+5 → прогон «на пять часов раньше»). Тот же приём —
   `parseIso` в админке.

Стражи — [`scripts/tests/test_frontend_freshness.py`](../../scripts/tests/test_frontend_freshness.py).

### Трек «Иски банка»: вторая картотека (v119, навигация v170)

Верхний сегмент-переключатель `Основные | Иски банка | ★ Мои`
(`#dataset-switch`, перед поиском) виден постоянно; банковский сегмент
добавляется при существующем `cases_bank.json` (HEAD-проба + персист
`bank_exists_v1` для офлайна, deep-link `?bank=1`, PWA-shortcut). Загрузка
**трёхступенчатая ленивая**: вход в картотеку → только список
(`loadBankDataset`, без events); первый клик чипа «Архив» →
`ensureBankArchive`; первое открытие drawer → `ensureBankEvents`
(`cases_bank(_archive)_events.json`, события подставляются всем делам разом,
в хронологии — спиннер; inline events старого монолита не перетираются).
Тяжёлые bank-файлы — таймаут 30 с (`FETCH_TIMEOUT_HEAVY_MS`).

С v169 переключатель оформлен как навигационный tab bar: единая нейтральная
платформа без внутренних разделителей и активный раздел на отдельной
приподнятой поверхности. С v170 контурная иконка оставлена только у «Моих»:
«Основные» и «Иски банка» показывают спокойные текстовые подписи со
счётчиками. Светлая и тёмная схемы используют свои `--scope-nav-*` токены.

**Пагинация рендера** (обе картотеки): `renderTable`/`renderMobileCards`
рисуют первые `RENDER_CHUNK=120` строк, дальше «Показать ещё» +
IntersectionObserver; фильтры/поиск/сортировка работают по всему датасету,
ограничен только DOM.

В bank-режиме: роль/инстанция основной картотеки скрыты и игнорируются
(значения не сбрасываются), категории пересобираются по активному датасету,
а отдельный контекст `Контроль` содержит `С ИЛ / Ждут ИЛ / Обеспечение`.
Bank-KPI «В производстве / Решено / С ИЛ / Ждут ИЛ» (`renderBankStats`)
переключают соответствующий общий статус либо банковский контроль;
«Ближайшие заседания» — по искам банка.
Архивность — track-осведомлённый `caseArchived` (у bank-дел решает только
файл-источник, `_bankArchived`).

**Watchlist**: звёзды работают в обеих картотеках. Bank-звезда хранится
composite-формой `«домен|номер»` (`caseCanonId`; номера не уникальны между
судами), основной трек — прежний bare-канон. «★ Мои» — **надкартотечный**
объединённый список звёзд обеих картотек (бейдж «🏦 Иск банка» на
bank-делах удалён 11.08.2026 решением юриста — роль видна из сторон).
Внутри «Моих» верхний переключатель не скрывается; bank-список и архив
подгружаются автоматически. Mine-дайджест и «Ближайшие заседания» используют
тот же строгий watchlist. При переезде
bank-дела в основной `cases.json` composite-звезда резолвится в bare-канон
через `buildWatchCanonMap` (composite-алиасы основных дел) — звезда
переживает переход.

### Глобальный поиск между разделами и честные счётчики (v167)

Разбор 10.08.2026: юрист предложил слить картотеки под ролевые фильтры —
отвергнуто (граница проходит не по роли, а по жизненному циклу: 58 из 59
«истцовых» дел основной картотеки — иски банка, переехавшие из трека при
апел. жалобе, `bank_case_left_track`). Вместо слияния:

- **Глобальный поиск** (`buildGlobalSearchTail`, `renderSearchCrossHint`):
  результат открытого раздела всегда первый; затем совпадения собираются без
  повторов в порядке `Мои → Основные → Иски банка`. Каждая часть получает

  действуют только на первую группу, для остальных переносится лишь строка
  поиска; горячие архивы не подмешиваются. Если bank-список ещё не загружен — единственная во
  фронте фоновая догрузка вне штатных триггеров, под тройным гардом
  `bankFileExists&&!bankLoaded&&!bankListLoading` + флаг
  `_crossHintLoadFailed` (не ретраить мёртвую сеть на каждый ввод).
  Глубина ленивой цепочки не растёт: архив и events ждут своих триггеров.
  Поисковый блоб — единый `caseSearchBlob` (и предикат `applyFilters`,
  и глобальные группы).
- **Честные счётчики**: знаменатели везде — АКТИВНЫЕ дела, архив — хвостом

  роль/инстанцию в bank-режиме; `archived_count` принимается только из
  `cases_bank.json` (`isBankListUrl`).

### Cache-bust — критическое правило

App-shell кэшируется cache-first, поэтому **при любой правке `app.js` или
`styles.css` обязательно**:

1. Инкрементировать `?v=N` в [`sberbank_dashboard.html`](../../sberbank_dashboard.html)
   у `<link href="styles.css?v=N">` (строка 72) и `<script src="app.js?v=N">`
   (строка 277);
2. Инкрементировать `CACHE_VERSION` в
   [`service-worker.js`](../../service-worker.js#L11).

Синхронность номеров проверяет тест `scripts/tests/test_versions.py` —
актуальное значение смотреть в [`service-worker.js`](../../service-worker.js#L11),
в этот файл его не дублируем (документ уже врал про «94» при фактическом
v118). Если забыть bump — у юриста на устройстве PWA
покажет старую версию из кэша (исторический инцидент — реактивация архива была
не видна, потому что забыли bump). Подробнее — раздел «Соглашения» в
[`CLAUDE.md`](../../CLAUDE.md).

Серверная часть (хранение подписок, админка) — в
[09. Cloudflare Worker](09-cloudflare-worker.md).
