# Техническая документация

Подробное описание того, **как устроена и как работает** система мониторинга
судебных дел ПАО Сбербанк: ХМАО, Урал, Башкортостан и Тюменская область; первая инстанция,
апелляция и кассация. Общий код используется в отдельных региональных копиях.

## Для кого это

Документация рассчитана на двух читателей сразу:

- **Юрист-владелец системы** — каждый документ открывается разделом «Что это и
  зачем» простым языком: что система делает, откуда берёт данные, как читать
  результат. Этого раздела достаточно, чтобы понять смысл компонента без кода.
- **Разработчик-преемник**, который будет сопровождать код — дальше идёт
  техническая часть: структуры данных, ключевые функции с путями и номерами
  строк, потоки выполнения, диаграммы.

Если вы быстро ищете «где в коде лежит X» — короткая карта-навигатор для этого
есть в корневом [`AGENTS.md`](../../AGENTS.md). `CLAUDE.md` ссылается на ту же
инструкцию. Эта папка — подробный справочник; исторические описания проверять
по текущему коду, особенно перед изменением расписания или доставки.

Исходная программа живёт в `codex/program`, региональные установки — в `main`
своих репозиториев. Версию установки определяет `.program-release.json`.
[Сборка и проверка выпуска](../Общая_программа.md). Состояние живых служб
проверяется отдельно по инструкциям [VPS](../../ops/vps-run/README.md).

## Где что лежит в региональной установке

```
dashboard/
├── scripts/update_cases.py     # Тонкий CLI-фасад
├── scripts/technical_report.py # Итоговый отчёт Actions и служебные события VPS
├── scripts/court_monitor/     # Парсеры, стадии, хранение, дайджест и доставка
├── scripts/add_cases_targeted.py # Точечные задания операторской формы
├── data/                       # cases.json + архивы + служебные снимки
├── app.js / sberbank_dashboard.html / styles.css   # SPA-дашборд (GitHub Pages)
├── service-worker.js / manifest.json                # PWA
├── cloudflare-worker/worker.js / wrangler.toml      # API подписок, админка, очистка профилей
├── ops/vps-run/                # Основной исполнитель: systemd + общие скрипты
├── ops/mac-local-run/          # Общий конвейер и ручной Mac-резерв
├── .github/workflows/*.yml     # GitHub Actions (replay_on_push — прод-дайджест)
└── docs/technical/             # ← вы здесь
```
