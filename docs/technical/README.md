> **Граница версий при публикации 14.09.2026:** главы описывают как
> опубликованную основу `1a943a7f` (очередь и отдельная доставка), так и

> и шлюза. Документационный коммит не выпускает этот код. Перед изменением

> [перечень различий](../Сверка_документации_2026-09-13.md).

Подробное описание того, **как устроена и как работает** система мониторинга
судебных дел ПАО Сбербанк: ХМАО, Урал и Башкортостан; первая инстанция,
апелляция и кассация. Общий код используется в отдельных региональных копиях.

## Для кого это

Документация рассчитана на двух читателей сразу:

- **Юрист-владелец системы** — каждый документ открывается разделом «Что это и
  зачем» простым языком: что система делает, откуда берёт данные, как читать
  результат. Этого раздела достаточно, чтобы понять смысл компонента без кода.
- **Разработчик-преемник**, который будет сопровождать код — дальше идёт
  техническая часть: структуры данных, ключевые функции с путями и номерами
  строк, потоки выполнения, диаграммы.

Если вы быстро ищете «где в коде лежит X» — короткая карта-навигатор для этого
есть в корневом [`AGENTS.md`](../../AGENTS.md). `CLAUDE.md` ссылается на ту же
инструкцию. Эта папка — подробный справочник; исторические описания проверять
по текущему коду, особенно перед изменением расписания или доставки.

> ℹ️ **Июль 2026: монолит распилен.** Код, который в этих документах
> исторически упоминался как «монолит `update_cases.py`», теперь живёт в пакете
> [`scripts/court_monitor/`](../../scripts/court_monitor/__init__.py)
> (config, textutil, netutil, courts, storage, health, lifecycle, parsing/,
> linking, digest/, delivery, runs); `scripts/update_cases.py` остался тонким
> CLI-фасадом с прежними флагами. Ссылки на код в главах переанкерованы на
> модули; имена функций и поведение не менялись.

> **Сверка по репозиторию 13.09.2026.** Основной парсинг и операторские импорты
> настроены на [VPS](../../ops/vps-run/README.md), который использует общие
> [скрипты Mac-звена](../../ops/mac-local-run/README.md); Mac остаётся резервом.
> Cloudflare cron в конфигурации отключён. GitHub `replay_on_push.yml` собирает
> гибридный дайджест после публикации данных; LLM-провайдер выбирается отдельно,
> в workflow по умолчанию OpenRouter. На VPS парсинг, импорт и доставка запускаются
> отдельными службами; поллер читает полную очередь, доставка повторяет попытки
> после 08:45 по собственному таймеру. Описание учитывает локальные изменения кода.
> Наличие файлов не доказывает состояние живых таймеров: перед операционными
> выводами проверять сервисы и настройки. Состав сверки и проверки — в
> [отчёте от 13 сентября](../Сверка_документации_2026-09-13.md).

## Где что лежит в репозитории

```
dashboard/
├── scripts/update_cases.py     # Тонкий CLI-фасад
├── scripts/court_monitor/     # Парсеры, стадии, хранение, дайджест и доставка
├── scripts/add_cases_manually.py
├── data/                       # cases.json + архивы + служебные снимки
├── app.js / sberbank_dashboard.html / styles.css   # SPA-дашборд (GitHub Pages)
├── service-worker.js / manifest.json                # PWA
├── cloudflare-worker/worker.js / wrangler.toml      # API подписок + админка (cron отключён)
├── ops/vps-run/                # Основной исполнитель: systemd + общие скрипты
├── ops/mac-local-run/          # Общий конвейер и ручной Mac-резерв
├── .github/workflows/*.yml     # GitHub Actions (replay_on_push — прод-дайджест)
└── docs/technical/             # ← вы здесь
```
