## Что решено и сделано (14.07)

- **Утверждённый план:** `~/.claude/plans/serialized-bouncing-quail.md` —
  архитектура inline-dispatch: поле `CourtConfig.source`, адаптер
  `sources/casebook.py` (2 функции, зеркалящие контракты `parse_first_instance_search`
  и `parse_case_card`), диспетчер в 2 точках `runs.py` (~1412/1421 и выше
  link-guard ~1650), митигации M1–M4 (дедуп по УИД; гейты health/капча-детекта;
  guard sudrf-URL; ссылки в дайджесте), слой перевода событий. План прошёл
  дизайн-воркфлоу (2 подхода → 3 судьи → 3 adversarial-критика) и самопроверку
  чтением кода. Архитектура **не привязана к Casebook** — поле `source` годится
  для любого альтернативного источника.
- **Ветка `feature/casebook-source`:** +15 строк в
  [courts.py](../scripts/court_monitor/courts.py) — `CourtConfig.source="sudrf"`
  (дефолт, все суды как были) + M3-guard `_require_sudrf` (sudrf-URL-методы на
  не-sudrf суде падают громко). 530 тестов зелёные. **НЕ закоммичено** — юрист
  не решил; закоммитить по его слову. `main` запушен полностью.
- **Этап 0 по скриншотам веб-UI Casebook** (дело 2-716/2025, Сургутский горсуд) —
  данные отличные:
  - события = **дословные формулировки ГАС «Правосудие»** («Вынесено решение по
    делу. Иск (заявление, жалоба) УДОВЛЕТВОРЕН») → слой перевода ≈ косметика;
  - **УИД есть** (`86RS0004-01-2024-013180-35`) и является полем поиска;
  - номер канонический + цепочка перенумерований `[2-9422/2024; М-7693/2024]`
    (адаптеру резать хвост `[…]` — наш `_bare_case_number` режет только `(`);
  - связанная апелляция прямо в карточке (`33-30/2026`), событие жалобы с ролью;
  - участники с **ИНН/ОГРН** (Сбербанк `7707083893`) → точный матчинг роли;
  - домен суда в точечной форме (`surggor.hmao.sudrf.ru` vs наш
    `surggor--hmao.sudrf.ru`) → нормализация при маппинге.
- **Осталось по Casebook** (заблокировано ответом про API): сам API-доступ
  (письмо администратору подписки юрист отправляет; веб-UI не автоматизируем),
  покрытие Академического р/с, текст акта (иконка 📄), будущие заседания,
  лаг синка Casebook↔ГАС.

## Задача новой сессии: альтернативные легитимные каналы

Проработать, сравнить, предложить юристу. Кандидаты по приоритету:

1. **`api.sudrf.ru` — официальный API ГАС «Правосудие»** (топ-кандидат).
   Бесплатный, без капчи, JSON, ключ по регистрации. По данным веб-разведки
   14.07 статус нестабилен («перенос БД на новые мощности, доступ временно
   приостановлен» — давность заметки неясна). Действия: проверить текущий статус
   (⚠️ из dev-сессии sudrf недоступен — TLS-дроп иностранных IP, см. память
   `project_geo_constraints`; проверять с Mac/RU-IP или workflow'ом с GitHub
   по образцу `probe_courts.yml`), найти процедуру регистрации, подготовить
   обращение на techportal.sudrf.ru (черновик — за Claude).
2. **Платные API-посредники** (легально отдают данные ГАС по подписке):
   Юрайт `you-right.ru` (~4,5–4,9 ₽/запрос, заявлен «мониторинг исков против
   юрлиц в СОЮ», JSON/iCal-календари), `api-assist.com`, `apiportal.ru`,
   `cyberjustice.ru` (единое API kad.arbitr + mos-gorsud + sudrf). Оценить:
   покрытие СОЮ и полей (движение дела, УИД, участники), цены, пробный доступ.
   Для банка потребуется закупка/ИБ — но чек мелкий по сравнению с Casebook.
3. **Другие подписки банка**: СПАРК-Интерфакс, Контур.Фокус — у банка почти
   наверняка есть; их модули судебных дел могут включать СОЮ-мониторинг с
   API/выгрузками. Вопрос юристу: что ещё лицензировано в юрдепе/комплаенсе.
4. **Остаться на текущем** для капча-судов: детект + 🩺-алерт (уже в проде) +
   ручная проверка. Академический пилот вручную, пока не появится канал.
   Ноль затрат — честный baseline для сравнения.
5. **cookie-reuse 3a** (отставлен, не запрещён): `probe_captcha.py --cookie`
   готов; если юрист согласен решать код руками раз в N дней — сначала замер
   срока жизни cookie (инструкция в старом хэндовере).

Для любого НОВОГО суда первый шаг всегда «шаг 0»: `probe_captcha.py` с RU-IP —
вердикт A означает «капчи нет, просто добавить суд», и никакой канал не нужен.
