# Тиражирование на территории: регионы и форки

Дата: 15.07.2026. Контекст: система тиражируется на отделения Уральского банка
(этап 1 — Свердловская область + ЯНАО; Челябинск/Башкирия/Тюмень/Курган —
отдельное планирование после проверки этапа 1). Полный план —
`~/.claude/plans/reactive-singing-thacker.md` (сессия 15.07.2026).

## Архитектура: «эталон + связанные копии»

- **Этот репозиторий — эталон** и одновременно боевой инстанс ХМАО.
- **Территория = форк** со своим GitHub Pages, Cloudflare Worker + KV,
  Telegram-чатом (бот общий), секретами и данными `data/`.
- **Форк НЕ правит общий код.** Всё регион-зависимое задаётся:
  - Actions Variables форка: `REGION=<код>` (модуль в
    `scripts/court_monitor/regions/`), `DASHBOARD_URL`;
  - тремя «файлами территории»: `region_front.js` (URL Worker'а + VAPID public
    key), `manifest.json` (имя PWA), `cloudflare-worker/wrangler.toml`
    (name воркера, `[vars]`, id KV, сдвинутый cron).
- Обновление форка: `git fetch upstream && git merge upstream/main`. На файлы
  территории и `data/**` в форке настраивается merge-driver `ours` (эталон
  ежедневно коммитит ХМАО-данные — иначе каждый merge конфликтовал бы).

## Регион как конфиг

- Типы — `scripts/court_monitor/regions/base.py`: `CourtConfig` (+ override-
  поля `delo_table/name_field/new_param` для нестандартных кассаций, напр.
  6-й КСОЮ Башкирии) и `RegionConfig` (код, имя, `appeal_courts` — **кортеж,
  апелляций может быть несколько**, реестр FI, кассация, маркеры матчера,
  `dashboard_url`, `public_info()` для фронта, `health_cassation_keys()`).
- Регионы — по модулю на территорию: `regions/hmao.py` (эталонный),
  далее `regions/sverdlovsk_yanao.py` и т.д. Все регионы живут в эталоне.
- Выбор — env `REGION` → `config.REGION` → `regions.get_region()` (ленивый
  importlib; неизвестный код падает громко). `courts.py` — фасад активного
  региона: `APPEAL_COURTS`/`APPEAL_COURT`/`FIRST_INSTANCE_COURTS`/
  `CASSATION_COURT` + `match_region_first_instance(name, region)`
  (`match_hmao_first_instance` — legacy-обёртка по активному региону).

## Мульти-апелляция (Свердловск+ЯНАО = облсуд + Суд ЯНАО)

- Блок `appeal` в cases.json хранит `court` / `court_domain` / `delo_id`;
  бэкфилл старых записей — `migrate_appeal_court_fields` (lifecycle, зовётся
  рядом с `migrate_stages`).
- Поиск апелляции в `main_json` — цикл по `APPEAL_COURTS`; карточки строятся
  по домену дела (`appeal_court_by_domain`).
- Связка `link_cases` ключуется парой `(домен апел-суда, номер)` — номера
  `33-…/YYYY` между двумя судами не уникальны.
- Дайджест показывает имя апел-суда только при нескольких судах в регионе
  (`details["appeal_court"]`); фронт берёт подпись/ссылку из `appeal.court*`.

## Фронт и инфраструктура

- Бэкенд пишет блок `region` в cases.json (`RegionConfig.public_info`) —
  app.js строит из него подписи/ссылки кассации (и апелляций — из полей дела)
  с ХМАО-фолбэком для старых данных.
- Worker: `ALLOWED_ORIGIN` / `CASES_DATA_URL` / `GH_REPO` — из `[vars]`
  wrangler.toml (фолбэки в коде = боевые значения ХМАО; чтобы vars
  применились, нужен `wrangler deploy`).
- Имена источников в админке «Здоровье парсеров» — из `parse_health.json`
  (поле `label` пишет `health.py`); карта `COURT_NAMES` в admin_page.js —
  временный фолбэк, удалить после пары прогонов.

## Капча (Свердловск и далее)

- Подтверждено (15.07.2026): капча гейтит ТОЛЬКО поиск; карточки
  `name_op=case` открыты. Боевой карточный путь защищён `fetch_card_checked`
  (netutil): капча на карточке → WARNING + метрика `cards_captcha` + пропуск,
  а не пустой «огрызок». Карточный детектор строже поискового: фразы
  «проверочный код»/«введите код» исключены — они встречаются в текстах
  актов о СМС-мошенничестве.
- Модель discovery для судов с капчей (вердикт C пробы `probe_captcha.py`):
  юрист решает капчу в браузере 1 раз → импортёр выдачи (этап 1, ещё не
  построен) достаёт `cid|cuid` → дальше автомониторинг карточек. Авторазгадка
  (OCR/ML/2captcha) — под запретом.

## Чеклист форка территории (этап 1, шаг 1.4 плана)

1. Fork репо → включить GitHub Pages.
2. Actions Variables: `REGION`, `DASHBOARD_URL`. Secrets: общие
   `ANTHROPIC_API_KEY`/`TELEGRAM_BOT_TOKEN`; свои `TELEGRAM_CHAT_ID*`,
   `PUSH_WORKER_URL`, `PUSH_SECRET`, `PROGRESS_SECRET`, `VAPID_PRIVATE_KEY`.
3. Cloudflare: новый Worker (имя в wrangler.toml), свой KV namespace,
   секреты Worker'а (`GITHUB_PAT`, `OWNER_SECRET`, `PUSH_SECRET`,
   `PROGRESS_SECRET`, `VAPID_PRIVATE_KEY`), `[vars]` под форк, cron со
   сдвигом (ХМАО — 03:45 UTC; территории — лесенкой позже).
4. Новая VAPID-пара: public — в `region_front.js` форка, private — в секреты.
5. `manifest.json`: имя PWA территории.
6. Очистить `data/` форка (пустой cases.json `version: 1`, пустые архивы).
7. Чат территории: добавить бота, снять chat_id.
8. Merge-driver `ours` на файлы территории и `data/**`.
