# Ожидание поздних кассационных актов

Выпуск 05.10.2026. Причина: дело 8Г-12188/2026 после отмены перешло в
`awaiting_relink` и выпало из чтения кассационных карточек. Исправлены номер,
суд, ссылка и начальная вкладка интерфейса. Общий выбор — `isCassationStage`.

## Независимое наблюдение

`scripts/court_monitor/act_watch.py` хранит задачи в `cases.json`, поле
`cassation_act_watch`. Ключ включает домен суда, раздел и номер производства;
ссылка и УИД проверяются дополнительно. Стадия дела не управляет задачей.
При запуске учитываются текущие блоки, история, горячие и холодные архивы,
включая bank-трек. Наблюдение начинается после появления `decision_date`
при отсутствии опубликованного текста.

До 30 дней включительно проверка ежедневная по рабочим дням; с 31 по 90 —
раз в 7 дней; после 90 — раз в 30 дней с предупреждением. Отсчёт интервала
ведётся от последнего успешного чтения. Капча, пустой ответ, ошибка разбора
и несовпадение реквизитов не обновляют его. Завершённые задачи не запрашивают
суд повторно. Новое рассмотрение не отменяет ожидание прежнего акта.

Очередь использует штатный транспорт и его предохранитель. Сведения о
запланированных и прочитанных карточках входят в дневную телеметрию.
Архивирование дела и ожидание текста теперь независимы: прежний срок
архивации не означает прекращения наблюдения за актом.

## Сохранение и дайджест

Задача фиксируется до HTTP и смены стадий. Полученный текст и событие
`pending_cassation_changes` сохраняются одной атомарной записью основного JSON.
При сбое записи прогон останавливается; событие нельзя считать обработанным.
Обновление архивного блока повторяемо после перезапуска. Архивные дела не
реактивируются, действующая стадия и новый круг не изменяются. Bank-архив
сохраняется через `save_bank_json` с отдельными событиями.

Для дайджеста сохраняется снимок сторон прежнего производства
`publication_parent`. Он проверяется по кассационному номеру и суду;
новое производство не подменяет стороны старого. Очередь событий удаляется
штатным подтверждением только после записи контекста дайджеста. Ранее
объявленные до постановки на наблюдение акты повторно не объявляются.

## Контроль

`parse_health.json.act_publication_watch`: дата, регион, waiting, due,
planned, read, published, unread, unplanned, long_wait и причины по карточкам.
В пульте это раскрываемый блок «Ожидание кассационных актов» в здоровье
парсеров. Отсутствующая ссылка и противоречивые реквизиты видны отдельно.

## Граница первого этапа

Этот выпуск вводит независимое наблюдение для кассации. Для апелляции
проверен существующий остановочный гейт после стадии `appeal`; для первой
инстанции — `should_parse_fi_card`. Их события и правила приёма существенно
отличаются от кассационных. Первый кассационный выпуск не включал независимое ожидание апелляционных
актов. Продолжение от 05.10.2026 описано отдельно:
[очередь апелляционных текстов](Ожидание_апелляционных_актов.md). Переходы
стадий апелляции сохраняются; ожидание её текста теперь выделено отдельно.
Первая инстанция остаётся за пределами обоих этапов.

Текст акта 8Г-12188/2026 восстановлен из карточки суда. Начало относится к
Петровой, но резолютивная часть опубликованного источника упоминает иные суды
и даты. Источник сохранён без исправления содержания. Дата акта 08.09.2026
не выдаётся интерфейсом за установленную дату его публикации.

## Интерфейс и чтение отчёта

В карточке дела v205 кассационный номер, суд и ссылка сохраняются при
`awaiting_relink`; при открытии сразу выбрана кассация. Номер апелляции
доступен на отдельной вкладке. «Дата опубликованного акта» — дата документа,
не установленный момент его размещения на сайте суда.

В админке блок находится в «Здоровье парсеров» и раскрывается нажатием
на заголовок. Счётчик `waiting` — оставшиеся незавершённые задачи после прохода,
включая требующие разбора; `planned` — запланированные запросы с подходящей
ссылкой; `read` — успешно прочитанные карточки; `unread = planned - read`.
`unplanned` включает конфликт реквизитов и отсутствие подходящей ссылки.
`long_wait` — ожидание более 90 дней от даты определения. Список `items`
может включать и акт, полученный в текущем проходе, с причиной `published`.

| Причина | Отображение и значение |
|---|---|
| `scheduled` | По расписанию: очередная проверка ещё не наступила |
| `text_not_published` | Карточка прочитана, текста пока нет |
| `published` | Акт получен в этом проходе |
| `unread_card` / `fetch_error` | Карточка не прочитана / ошибка запроса; успешная дата не сдвигается |
| `missing_card_link` | Нет корректной ссылки для запроса |
| `identity_conflict` | Противоречивые реквизиты: задача требует разбора |
| `identity_mismatch` | Полученная карточка не соответствует ожидаемому делу |
