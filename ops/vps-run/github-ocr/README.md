# Капча, пересказы и Telegram на российском VPS

С 15 ноября 2026 года российский VPS ведёт сессию суда ХМАО и обращается к
OpenRouter через зарубежный VPS. При сбое соединения используется GitHub.
После готовности резерва парсер получает свежую форму суда.

## Резерв капчи

`/etc/court-github-ocr/config.json` с `{"enabled": true}` включает обмен.
Без файла сохраняется прежний транспорт. Некорректный файл останавливает
поиск, а не переводит его незаметно на старый маршрут. Настройка действует
только для уже разрешённого флагом пилота ХМАО.

Парсер создаёт случайный Unix socket в `/run/court-github-ocr`, затем вызывает
workflow_dispatch для `SelivanovAS/dashboard`, workflow `github_captcha.yml`,
ref `main`. Токен API читается из отдельного root-only файла
`/etc/court-github-ocr/github-token`, не из региональных env. В GitHub уходят
только ID запроса и срок подключения. Ожидание готовности ограничено 120 с и
остатком общего дедлайна с резервом 60 с. После готовности начинается прежний
бюджет поиска 180 с. Число попыток, модели и предел четырёх вызовов сохранены.

Runner подключается к российскому серверу как `court-gh-ocr`. ForceCommand
разрешает только `github_captcha_bridge.py` и ID из 32 hex-символов. Shell,
port forwarding, агент и терминал недоступны. Парсер проверяет UID подключившегося
процесса и точный ID запуска GitHub. Поздний запуск не найдёт закрытый socket.
Картинка и код передаются по SSH в памяти; в Git, артефакты и логи не пишутся.
Для распознавания worker допускает две закреплённые модели, PNG и прежний промпт.
Отдельная команда открывает TLS к api.telegram.org:443. Сертификат проверяет
российский VPS, ключ Telegram передаётся только внутри TLS.

Secrets ХМАО: `OCR_SSH_PRIVATE_KEY`, `OCR_SSH_KNOWN_HOSTS` и существующий
`OPENROUTER_API_KEY`. Variable: `OCR_SSH_HOST`. Приватный SSH-ключ даёт только
доступ к существующему сеансу капчи; ключ OpenRouter на VPS для этого режима
не требуется. Host key берётся через уже доверенное административное соединение.

Установка SSH-пользователя, root-owned authorized_keys, sshd Match User и
tmpfiles.d выполняется отдельно от пакета. Каталог socket: root:court-gh-ocr,
0750; отдельный socket — 0660. Правило tmpfiles восстанавливает каталог после
перезагрузки. Файл API-токена — root:root 0600. При замене токена права сохранять.

## Утренний выпуск

При `CM_VPS_RELEASE=1` региональный парсер копит тексты. В окно доставки
российский VPS собирает дайджест в отдельной копии картотеки. Региональные
ключи OpenRouter лежат в закрытом каталоге
`/srv/projects/sbersud/private/release`. Запросы модели идут через локальный
прокси 18129. При отказе местной сборки до назначения отправителя прежний
replay GitHub принимает этот выпуск целиком.

При успешной сборке маркер содержит SHA-256 файла дайджеста. GitHub сверяет
его с выпуском, проверяет публикацию Pages и выполняет обычный Web Push.
Российский VPS получает результаты этого же запуска, добавляет их к местному
отчёту и отправляет его в личный Telegram через туннель. При отказе TLS
до передачи сообщения открывается резервное соединение через GitHub.
Если через 20 минут подтверждения публикации ещё нет, ближайший штатный слот
отправляет отчёт с явной отметкой об этом. История выпуска хранится в
`/srv/projects/sbersud/private/release-jobs/<регион>/<хэш delivery_id>/`.
После потери ответа Telegram части со статусом `sending` или `unconfirmed`
сверяют с личным чатом до ручного решения о повторе.

## Проверка и возврат

Для проверки связи Telegram использовать метод `getMe`. Для проверки модели
использовать вымышленный текст и временный каталог. Готовый выпуск можно
проверить на копии командой `local_release.py verify` с закрытым временным
файлом `TECHNICAL_REPORT_PATH`. Функция подготовки не отправляет уведомлений.
Для возврата будущих выпусков на обычный replay выключить `CM_VPS_RELEASE`
после завершения уже сохранённых личных отчётов. Возврат программы выполняется
пакетом через `program_release.py`.
