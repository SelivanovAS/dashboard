# Автоматическое сжатие истории VPS

Эти файлы обслуживают весь сервер отдельно от регионального пакета программы.
Они не устанавливаются обычным обновлением регионов и не требуют изменения
`deployment/manifest.json`. На новом сервере их нужно установить отдельно.

## Поведение

`court-history.timer` запускает проверку ежедневно в 03:17
`Asia/Yekaterinburg`, с точностью планировщика до минуты. Пропущенный при
выключенном сервере запуск не догоняется днём (`Persistent=false`). Mac для
работы расписания не нужен.

Скрипт обслуживает четыре репозитория в `/opt/court-monitor`: `dashboard`,
`dashboard-tyumen`, `dashboard-bashkortostan`, `dashboard-ural`.
Переупаковка нужна, когда есть хотя бы 256 отдельных объектов, 16 МиБ таких
объектов или 8 файлов упаковки. Уже компактные репозитории пропускаются.

Все версии сохраняются, включая недостижимые объекты для восстановления.
Используется `git repack -a -d -n --cruft --threads=1 --window-memory=32m`
без срока удаления. Ветки и история коммитов не переписываются; fetch/push,
парсинг и рассылки не выполняются. Сжатие не устанавливает предел общего
размера истории: новые версии продолжают накапливаться.

Защита работы сервера:

- Общая `.program-install.lock` исключает параллельную установку программы.
  При занятой блокировке проход пропускается; незавершённые
  `.program-install-*.json` останавливают обслуживание с ошибкой.
- Каждый репозиторий использует штатный `ops/mac-local-run/run_lock.py` и
  `.run.lock`; занятый регион пропускается до следующего прохода.
- Перед переупаковкой требуется свободное место: 512 МиБ плюс удвоенный
  текущий размер отдельных и упакованных объектов.
- До и после сжатия выполняется `git fsck`; сравниваются все идентификаторы
  объектов и ссылки Git. При ошибке служба завершается с ненулевым кодом.
- При остановке дочерние процессы Git завершаются до освобождения блокировки.
- Низкий приоритет CPU/диска, CPUQuota 50%, MemoryHigh 256M,
  MemoryMax 384M, общий предел времени 45 минут.

## Установка

Проверить целевой сервер и наличие всех четырёх репозиториев, Python 3,
Git с поддержкой `--cruft`, systemd и штатного `run_lock.py` в каждом клоне.
На исходном сервере проверены Ubuntu 24.04 и Git 2.43.0.
Перед заменой уже существующих файлов сохранить их копии и сравнить изменения.

Выполнить от root из этого каталога, предварительно скопированного на сервер:

```sh
install -m 0644 court-history.py /usr/local/lib/court-history.py
install -m 0644 court-history.service /etc/systemd/system/court-history.service
install -m 0644 court-history.timer /etc/systemd/system/court-history.timer
systemd-analyze verify /etc/systemd/system/court-history.service /etc/systemd/system/court-history.timer
systemctl daemon-reload
systemctl start court-history.service
systemctl show court-history.service -p Result -p ExecMainStatus
journalctl -u court-history.service -n 30 --no-pager
```

Только после успешного пробного запуска (`Result=success`, `ExecMainStatus=0`)
и проверки журнала включить расписание:

```sh
systemctl enable --now court-history.timer
systemctl list-timers court-history.timer --no-pager
```

`SKIP busy` означает пропуск занятого региона, а не выполненное сжатие.
Успешный выход oneshot-службы оставляет её `inactive`; активным должен быть таймер.
При нехватке места или ошибке целостности проверить причину по журналу;
не удалять версии и блокировки для обхода ошибки.

## Отключение

```sh
systemctl disable --now court-history.timer
```

Это отменяет будущие запуски. Если обслуживание уже выполняется, дождаться
его завершения либо отдельно выполнить `systemctl stop court-history.service`.
Отключение не меняет данные и не распаковывает историю обратно.

## Проверка сохранности

Из корня исходного проекта:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 ops/vps-run/history/test_court_history.py
```

Проверка создаёт временный репозиторий и проверяет сохранность рабочих файлов,
ссылок и всех объектов, включая недостижимые; пропуск занятого lock,
освобождение своего lock при ошибке и исключение незавершённой установки.
Боевые репозитории тест не использует.
