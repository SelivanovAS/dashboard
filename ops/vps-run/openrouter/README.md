# Выделенный маршрут OpenRouter

На российском VPS `court-openrouter-tunnel.service` слушает только
`127.0.0.1:18129` и пересылает CONNECT к закрытому tinyproxy на финском VPS
`89.35.129.115:127.0.0.1:18889`. Прокси допускает только `openrouter.ai:443`.
TLS до OpenRouter проверяется самим клиентом и не расшифровывается прокси.

В `env.hmao` включается ровно `OPENROUTER_PROXY_URL=http://127.0.0.1:18129`.
Настройку читают только вызовы капчи, генерации/полировки и каталога OpenRouter.
Глобальные HTTP_PROXY/HTTPS_PROXY не задаются; запросы к судам идут напрямую.
Отключение туннеля приводит к ошибке модели, а не к прямому повтору.

Шаблоны устанавливаются отдельно от пакета: proxy.service/tinyproxy.conf и
allowed-domains на финский сервер; tunnel.service на российский. Отдельные
пользователи: court-or-proxy, court-or-forward (Финляндия), court-or-tunnel (РФ).
Ключ генерируется на российском VPS в /etc/court-openrouter-tunnel; приватный
ключ не копируется, на финский сервер передаётся только публичный. Host key
проверяется по существующей доверенной записи. SSH разрешает этому пользователю
только пересылку к 127.0.0.1:18889; вход паролем и shell-сессии выключены.

Проверки: GET /api/v1/key через локальный прокси; запрет CONNECT к суду и иному
домену; прямое чтение суда; модельный ответ и принятие капчи судом отдельно.
Запуск теста модели может расходовать средства. Не запускать replay ради пробы:
он связан с Telegram и Web Push. Существующий Telegram-туннель независим.

Откат: убрать только OPENROUTER_PROXY_URL из env.hmao и отключить новый туннель;
прямой доступ к OpenRouter при действующей блокировке снова вернёт 403.
Не менять таймеры парсинга, доставки и импорта. Установка файлов программы
выполняется штатным координатором program_release.py.
