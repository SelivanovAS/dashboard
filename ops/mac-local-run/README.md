# Автозапуск парсинга на Mac (вариант D2) — ⏳ ВРЕМЕННОЕ решение

> **Это временная схема.** В будущем парсинг переедет на сервер (российский
> VPS: точечный прокси для судов либо полный перенос прогона), после чего всё
> из этого каталога демонтируется по разделу «Откат» ниже, а расписание
> вернётся в инфраструктуру.

> 💤 **СТАТУС на 05.07.2026 — спящий резерв.** Суды снова пускают US-IP GitHub
> (блок 02.07 сняли, проверено `.github/workflows/probe_courts.yml`), автозапуск
> вернулся в облако (Cloudflare Worker cron → `update_cases.yml`). Эта Mac-схема **усыплена**, но
> не демонтирована — держим как запасной путь на случай возврата блока. Команды
> усыпить/разбудить — в разделе [«Резерв: усыпить/разбудить»](#резерв-усыпитьразбудить).
> Ниже описание для случая, когда схема активна.

Суды (`*.sudrf.ru`) режут TLS с иностранных IP, поэтому GitHub Actions (США)
больше не может парсить суды. Этот Mac физически в сети Сбера (выход в интернет
российский) → **парсинг делаем здесь**, а тяжёлый Claude-дайджест и рассылку
оставляем на GitHub (там Claude доступен).

```
┌─ Mac (по будням) ──────────────┐        ┌─ GitHub Actions ───────────────┐
│ parse_and_push.sh:             │  push  │ replay_on_push.yml:            │
│  • маршрут судов мимо VPN       │ ─────► │  • видит новый                 │
│  • update_cases.py --json      │  git   │    last_digest_context.json    │
│  • git commit + push           │        │  • --replay-last --push-all    │
│    (БЕЗ секретов)               │        │  • Claude-дайджест → Telegram  │
└────────────────────────────────┘        │    + Web Push всем подписчикам │
                                           └────────────────────────────────┘
```

Секретов на Mac нет. Доставка при локальном прогоне сама пропускается, дайджест
получается шаблонным (его выбрасывают) — важен только сохранённый **контекст**,
из которого GitHub соберёт настоящий дайджест.

## Что уже готово в репозитории

- `parse_all.sh` — драйвер территорий: гоняет по каждому клону **подряд**
  сначала парсинг, потом разбор очереди импортов. Его и зовёт LaunchAgent.
- `cloud_run_ok.py` — гейт подстраховки: был ли сегодня ЗРЯЧИЙ облачный
  прогон (по журналу здоровья парсеров). Зрячий → Mac не парсит (иначе два
  дайджеста всем); слепой (адрес раннера заблокирован — нули по всем
  источникам) или прогона не было → Mac парсит сам. `--force` обходит.
- `import_all.sh` — разбор очереди импортов по всем территориям БЕЗ парсинга;
  висит на своём агенте `com.court-monitor.import` (будни 10:30–18:30 каждые
  2 часа — оператор кормит дампы до вечера, облако часть теряет).
- `СберСуд-пульт.command` — двойной клик: в шапке статус облака по
  территориям (человеческими именами), очередь дампов и состояние автоматики;
  меню — парсинг сейчас (в выходной спросит «всё равно прогнать?») · дампы
  сейчас · живой лог · проверка · включить/починить автоматику · открыть
  дашборд и админку. ⌘. прерывает текущее действие и возвращает в меню.
  Старый ярлык «Парсинг судов.command» открывает его же.
- `parse_and_push.sh` — обёртка одного клона (preflight, маршрут, парсинг,
  commit/push). Путь к клону — первый аргумент или env `CM_REPO`.
- `delivery_txn.py` — атомарный локальный journal доставочного marker-коммита:
  различает подготовку, локальный commit и подтверждение remote после
  неоднозначного `git push`; новый слот сначала доводит эту транзакцию.
- `import_dumps.sh` — разбор очереди операторских импортов: дампы капчёвых
  судов и точечные пачки «Добавить дела» (см.
  [«Очередь операторских импортов на Mac»](#очередь-операторских-импортов-на-mac)).
- `lib_sber_net.sh` — общий слой обоих скриптов: сеть Сбера, маршруты судов
  мимо VPN, проба доступности, ssh-адрес origin, 🚨-алерт. Копия преflight'а во
  втором скрипте разъехалась бы так же, как разъезжались списки файлов данных.
- `import_queue.jq` — какие записи резерв забирает из журнала Worker'а;
  `../import_result_body.jq` — тело отчёта оператору, ОДНО с облаком.
- `run_parse.py` — запуск `main_json` без секретов (глушит `validate_environment`,
  иначе `exit(2)`); обёртка зовёт его.
- `com.court-monitor.parse.plist` — LaunchAgent парсинга (будни 06:00–08:30
  каждые 30 мин + доставочный 08:45 — расписание 21.08.2026 «парсинг с 06:00,
  дайджест не раньше 08:45»; слоты до окна копят новости молча, отправляет
  первый слот, завершившийся после 08:45; 08:45 — последний, страховки после
  него нет). `com.court-monitor.import.plist` — LaunchAgent дампов (будни
  10:30–18:30 каждые 2 часа).
- `court-monitor-route.sudoers` — правило sudo для команды `route`.
- `../stage_data_files.sh` — какие файлы данных коммитить. Список ОБЩИЙ с
  облаком: он спрашивает пути у `court_monitor.config`. Прежде список вёлся
  руками и здесь, и в `update_cases.yml`, и они молча разъехались — резерв не
  коммитил семь файлов трека «Иски банка» (трек появился 25.07.2026, уже после
  того, как резерв усыпили).

Локальные runtime-файлы лежат в `ops/mac-local-run/.runtime/` и игнорируются
Git: `parse_telemetry.json` — непрерывный checkpoint текущей фазы, покрытия и
transport/semantic исходов HTTP; `delivery_txn.json` — незавершённая доставка.
Оба файла атомарны и переживают SIGKILL/сон. В коммиты они не попадают.
Telemetry содержит host, короткий context (в том числе номер
дела) и, если его печатает страница защиты, диагностический IP/букву
правила. HTML, полный URL карточки, стороны и тексты судебных документов в
файл не пишутся; telemetry-файл каждый раз публикуется из
временного файла с правами `0600`.

Mac-слот задаёт `FETCH_MAX_RETRIES=3`, но это только потолок: сетевой слой
повторяет быстрый `connection_reset`/5xx (не дольше 5 секунд), а ReadTimeout,
connect-timeout, 4xx, CAPTCHA и HTTP-200-заглушку завершает после первой
попытки. Так мигающий портал дочитывается, а медленный не умножает ожидание.

## Настройки машины (вне репозитория)

Каталог `~/.config/court-monitor/`. Всё необязательное: нет файла — прежнее
поведение.

| Файл | Зачем |
|---|---|
| `territories` | Пути к клонам, по строке; `#` — комментарий. Нет файла → только `~/dashboard`. |
| `env.<регион>` | Переменные территории (`BANK_INTAKE_MAX_PER_RUN=200` и т.п.). В облаке это Actions Variables, на Mac их взять неоткуда — без файла подхват идёт с дефолтами кода. |
| `telegram` | `token=…` и `chat_id=…` — 🚨-алерт при падении прогона. Без него только уведомление на экране, а слоты идут рано утром. |
| `progress_token` | Токен живого лога прогона в админку Worker'а. |
| `worker.<регион>` | Адрес и секреты Worker территории для очереди импортов: `url=`, `owner_secret=`, `push_secret=` (chmod 600). Нет файла → очередь не разбирается, остаётся только `--file`. |

Пример `territories`:

```
/Users/aleksandrselivanov/dashboard
/Users/aleksandrselivanov/dashboard-ural
```

Клон второй территории ставится как обычный клон форка, плюс обязательно
`git config merge.ours.driver true` (без него merge из эталона затрёт файлы
территории). Регион клон определяет сам — по файлу `REGION` в его корне.

## Установка (делается один раз)

Предполагается репозиторий в `/Users/aleksandrselivanov/dashboard`. Зависимости
(`requests`, `pywebpush`) уже стоят в пользовательском Python 3.9.

### 1. Разрешить добавление маршрута без пароля

Маршрут судов мимо VPN требует root. Чтобы launchd не завис на вводе пароля —
кладём узкое правило sudoers:

```bash
cd /Users/aleksandrselivanov/dashboard
sudo cp ops/mac-local-run/court-monitor-route.sudoers /etc/sudoers.d/court-monitor-route
sudo chmod 440 /etc/sudoers.d/court-monitor-route
sudo visudo -c          # должно вывести «parsed OK» по всем файлам
```

### 2. Поставить LaunchAgent

```bash
cp ops/mac-local-run/com.court-monitor.parse.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.court-monitor.parse.plist
launchctl list | grep court-monitor        # убедиться, что загрузился
```

Время запуска — **слоты 06:00–08:30 каждые 30 мин + доставочный 08:45** по
местному (Ханты-Мансийск, +05). Поменять — в plist (`Hour`/`Minute`), затем
`launchctl unload … && launchctl load …`. ⚠️ Последний слот и окно доставки
(`DELIVERY_WINDOW_MIN` в `parse_and_push.sh`) держать ПАРОЙ: слот раньше окна
превратит дайджест в черновик и отложит до завтра (страж
`test_delivery_slot_matches_window`).

### 3. Отключить старый автозапуск через Cloudflare Worker

Иначе GitHub каждое утро будет пытаться (и не мочь) спарсить суды и слать 🚨.
В `cloudflare-worker/wrangler.toml` уже проставлено `crons = []`; осталось
задеплоить:

```bash
cd /Users/aleksandrselivanov/dashboard/cloudflare-worker
wrangler deploy
```

### 4. Проверить GitHub-секреты

Workflow `replay_on_push.yml` использует те же секреты, что и `update_cases.yml`
(`ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID_TEST`,
`PUSH_WORKER_URL`, `PUSH_SECRET`, `VAPID_PRIVATE_KEY`) — они уже есть, ничего
добавлять не нужно.

отработает `replay_on_push` и в личный Telegram придёт Claude-дайджест.

Прогон из-под самого launchd (без ожидания слота):


## Очередь операторских импортов на Mac

Операторские каналы умирают вместе с облаком. Оператор решает проверочный
код капчёвого суда, вставляет выдачу в админку → Worker кладёт дамп в KV и
запускает `import_cases.yml`. Пока суды режут адреса раннеров, облачный импорт
заводит **ноль**: правила приёма исков банка решаются только по карточке, и
строка выдачи теряется целиком (16.08.2026, Урал: `+0 в картотеку · 10 карточка
не открылась`). Cloudflare и KV при этом живы — на sudrf они не ходят.

`import_dumps.sh` делает ту же работу отсюда: забирает журнал импортов
(`/admin/import-log`), берёт из KV записи, которые облако не довело **или
довело с потерями**, гоняет тот же импортёр, коммитит и отправляет сводку
обратно в админку. Оператор ничего нового не делает — он видит в журнале ту же
запись, только с настоящими числами, и с пометкой `🖥 повтор с локальной
машины`.

**Каналов в очереди два** (с 23.08.2026):

| Канал | Задание из KV | Скрипт | Признак потери |
|---|---|---|---|
| Дампы выдачи (`import:dump:`) | `GET /import-dump?key=` | `scripts/import_search_dump.py` | `fetch_fail` (иск банка не заведён), `card_failed` (дело заведено пустышкой) |
| Точечные пачки (`import:case:`) | `GET /add-case-job?key=` | `scripts/add_cases_targeted.py` | `fetch_error` (строка потеряна целиком) |

Пачки добавились не для симметрии: в **ссылочном** режиме — а для капчёвых
судов он единственный — непрочитанная карточка убивает строку ЦЕЛИКОМ. Роль
банка определяется только по карточке, поэтому card-blind записи, как у
дампов, там не выходит, и до 23.08.2026 такая строка просто исчезала: пачка
тихо истекала в KV через сутки. Пачки живут на ЛЮБОЙ территории, поэтому
скрипт теперь работает и там, где капчёвых судов нет вовсе (ХМАО) — тишину
держит отсутствие `worker.<регион>`, а не отсутствие капчи.

```bash
# Диагностика по пунктам — ничего не меняет, запускается и из дома:
# сеть Сбера и суды (только из офиса) + настройки Worker'а + сколько записей
# в очереди прямо сейчас. Отвечает прямо в терминал.
bash ops/mac-local-run/import_dumps.sh ~/dashboard-ural --check

# Холостой заход: что забрал бы и что завёл бы. Ничего не пишет и не коммитит
bash ops/mac-local-run/import_dumps.sh ~/dashboard-ural --dry-run

# Проверка ВНЕ офиса (дома): не требовать шлюз Сбера. Суды всё равно обязаны
# ответить по-настоящему — через корпоративный VPN они отдают 403, поэтому
# VPN на время проверки надо выключить. Ежедневный запуск ключа не получает.
bash ops/mac-local-run/import_dumps.sh ~/dashboard-ural --check --anywhere

# Боевой разбор очереди
bash ops/mac-local-run/import_dumps.sh ~/dashboard-ural
tail -f ops/mac-local-run/import_dumps.log

# Дамп, которого в KV уже нет (TTL 24 ч) или присланный файлом
bash ops/mac-local-run/import_dumps.sh ~/dashboard-ural \
  --file ~/Downloads/выдача.html --court leninskiy--svd.sudrf.ru
```

Отдельно запускать обычно не нужно: `parse_all.sh` разбирает очередь следом за
парсингом каждой территории (отказ импорта прогон не валит).

Что нужно машине: `~/.config/court-monitor/worker.<регион>` c тремя строками —

```
url=https://court-monitor-ural.7selivanov-a.workers.dev
owner_secret=…
push_secret=…
```

`chmod 600`. Секреты те же, что у Worker'а территории (`OWNER_SECRET` и
`PUSH_SECRET`); файл читается `awk`, а не `source`, — иначе `PUSH_SECRET` и
`PUSH_WORKER_URL` попали бы в окружение прогона и включили бы вторую доставку
push с Mac. Нет файла — очередь просто не разбирается, `--file` работает.

Правила выборки (`import_queue.jq`) — запись моложе суток (TTL KV в обоих
каналах), и либо облако её не довело, либо довело с потерями. Успешный отчёт
резерва обнуляет счётчики потерь — поэтому локальной памяти «уже сделано» нет
вовсе: следующий заход ту же запись просто не выберет. Повтор в любом случае
безопасен: дедуп отсеет заведённое, а дела, заведённые без карточки, дочитает
`[REFILLED]`.

Что различается между каналами:

- **Грейс живого облачного джоба.** У дампов 15 минут (`import_cases.yml`
  стоит на `timeout-minutes: 15`), у пачек — **50** (`add_cases.yml` стоит на
  45: до 20 номеров × все открытые суды с вежливой паузой честно идут
  полчаса). С дамповым грейсом Mac полез бы писать в те же файлы посреди
  живого джоба.
- **Статус `dispatched` у пачек** — тоже застревание: у GitHub-группы
  `cases-data-write` живёт ОДИН pending, и запись может простоять в этом
  статусе всю очередь. Берём её после того же грейса.
- **Пачку повторяем ЦЕЛИКОМ**, а не одни упавшие строки: отчёт перезаписывает
  счётчики записи журнала, и повтор двух строк из двадцати оставил бы
  оператору сводку «+2 добавлено», спрятав исходные 18.
- **Пометки «лист не нужен»** (`import:writ:`) очередь не берёт никогда — к
  судам они не ходят, дочитывать в них нечего.

⚠️ Выдача задания пачки (`GET /add-case-job`) до 23.08.2026 принимала только
`PUSH_SECRET`, которого на этой машине взять неоткуда (он write-only и в
Cloudflare, и в GitHub secrets). Теперь роут стоит на общем `importChannelAuthOk`
— как `/import-dump` с 16.08.2026.

## Как это себя ведёт

- **Best-effort по времени.** LaunchAgent срабатывает в залогиненной сессии.
  Если Mac спал/выключен — пропущенный слот проиграется при пробуждении/входе
  (после 08:45 такой прогон сразу доставит накопленное). День, когда Mac вовсе
  не открывали, останется без дайджеста.
- **Слот ≠ гарантированный запуск.** Пока агент работает, наступивший интервал
  launchd пропускает БЕЗ очереди (замер 21.08.2026: старт 08:00, финиш 09:02 —
  слоты 08:30 и 09:00 не запускались, следующий пуск 09:30). Прогон двух
  территорий ~60 мин (с ретраями больше, на дочитке повторные слоты быстрые),
  так что реально за утро проходит 2–4 попытки, а не 7. Дайджест это не рвёт:
  прогон, идущий в 08:45, доставляет сам — окно проверяется по времени финиша.
- **Не в сети Сбера** (из дома, другой Wi-Fi) → обёртка покажет уведомление
  «Пропуск: не в сети Сбера» и ничего не сделает. VPN при этом можно не трогать
  — для парсинга он не нужен (а если поднят, маршрут судов его обходит).
- **Праздники РФ** пропускаются автоматически (`SKIP_NON_WORKING_DAYS=1`).

**На Mac — ярлык «Парсинг судов.command»** (копия лежит на рабочем столе,
оригинал здесь в каталоге). Двойной клик → открывается окно: текущий (или
последний) прогон **с самого начала** + живое продолжение. Прокрутка вверх —
прошлые прогоны. Закрыть окно — ⌘W, на парсинг не влияет.

**Из браузера/с телефона — блок «🛰 Парсинг» в админке подписчиков**
(`https://court-monitor-trigger.7selivanov-a.workers.dev/admin?secret=<OWNER_SECRET>`).
Обёртка запускает `progress_pusher.py`: он читает лог, фильтрует вехи
(апелляция, каждый суд, кассация, ошибки, финал) и раз в ~5 с шлёт их на
`POST /run-progress` Worker'а. Блок в админке автообновляется, пока прогон
не завершён; хранится также предыдущий прогон.

Токен для отправки вех: `~/.config/court-monitor/progress_token` (chmod 600,
**вне репозитория** — репо публичный). То же значение должно лежать в секрете
Worker'а: `wrangler secret put PROGRESS_SECRET`. Нет токена → вехи просто не
шлются, парсинг работает как обычно.

## Логи

- `parse_and_push.log` — основной лог обёртки (парсинг, маршруты, git).
  При смене даты вчерашний файл уходит в `parse_and_push-ГГГГММДД.log`, окно
  истории — 14 дней (`CM_LOG_KEEP_DAYS`); страховочный предел большого
  дневного файла — 4000 строк с сохранением последних 2000.
- `.runtime/parse_telemetry.json` — последний живой checkpoint и три прошлых
  прогона; при следующем старте оставшийся `running` станет `interrupted`.
- `.runtime/delivery_txn.json` — существует только пока судьба marker-коммита
  не установлена. При `unknown` удалять вручную нельзя: сначала надо проверить
  remote, иначе возможен повторный replay.
- `launchd.out.log` / `launchd.err.log` — что видит launchd.

## Резерв: усыпить/разбудить

С 05.07.2026 основной автозапуск — в облаке (крон в `update_cases.yml`), а эта
схема держится как **спящий резерв** (файлы и плист на месте, LaunchAgent

**Усыпить** (перевести в резерв — плановый Mac-прогон больше не стартует):

```bash
launchctl unload ~/Library/LaunchAgents/com.court-monitor.parse.plist

```

**Разбудить** (если суды снова закрыли иностранные IP — см. «Процедура флипа» в
CLAUDE.md). ⚠️ Сначала со стороны облака: **отключи Worker-крон** (верни

дайджест-на-push** (в `.github/workflows/replay_on_push.yml` верни
`if: github.actor != 'github-actions[bot]'` вместо `if: false`, коммит). Затем на Mac:

```bash
launchctl load ~/Library/LaunchAgents/com.court-monitor.parse.plist
launchctl list | grep court-monitor   # должен появиться
```

Проверить, что блок судов действительно вернулся, можно заранее: Actions → workflow
`🔬 Проба доступа к судам с GitHub (US-egress)` → Run workflow.

## Откат (полный демонтаж — не путать с усыплением)

```bash
launchctl unload ~/Library/LaunchAgents/com.court-monitor.parse.plist
rm ~/Library/LaunchAgents/com.court-monitor.parse.plist
sudo rm /etc/sudoers.d/court-monitor-route
```

Вернуть автозапуск через Worker — раскомментировать `crons` в `wrangler.toml`
и `wrangler deploy`.
