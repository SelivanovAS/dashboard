# Репетиция импортов и закрытый пилот ХМАО

Адаптер `isolated-import.mjs` / `isolated_import.py` запускает существующие
импортёры с настоящими парсерами, правилами приёма и сохранением. Подставляется
только HTTP-транспорт. В режиме `isolated` файл `responses.json` сопоставляет URL с синтетическим HTML
или ошибкой. Внутри импортёра запрещены настоящие сокеты, дочерние процессы и
shell; секреты пользовательского окружения не наследуются. Git, отправки и
модельные вызовы не выполняются. Рабочие API, DNS и расписания не изменяются.

## Подготовка копии и конфигурации

Нужны зависимости из [README.md](README.md). При нескольких Python укажите
`TEST_PYTHON=/absolute/venv/bin/python`: это выбор интерпретатора, а не
переключатель изолированности.

Подготовьте закрытый канонический каталог. На macOS используйте путь после
`realpath`, без алиасов `/var`/`tmp`. Структура:

```text
.sbersud-isolated.json     {"region":"hmao","synthetic":true}
current.json              {"version":"initial"}
responses.json            {"region":"hmao","synthetic":true,"responses":{"https://...":{"body":"<html>...</html>"}}}
snapshots/initial/data/    полный синтетический снимок, включая архивы и события
```

Отсутствующий URL или `{"error":true}` имитирует сетевой отказ. Сам маркер не
превращает рабочую картотеку в изолированную: применять только к отдельной
синтетической копии. В режиме `isolated` каталоги `/opt` и `/srv`, символические и жёсткие ссылки
запрещены. Главный JSON содержит `region.code`; bank JSON может унаследовать
регион из главного. Полные исполняемые примеры данных и сетевых ответов —
[tests/imports.test.mjs](tests/imports.test.mjs).

При запуске `configure.py` добавьте
`--publication-root /absolute/private/hmao-publication`. Остальные параметры
генератора остаются прежними. API и исполнитель должны указывать на одну
публикацию — несовпадение останавливает задание до применения.

```sh
node server-api/cli.mjs publication-init /absolute/private/hmao-config.json /absolute/private/hmao-publication
node server-api/server.mjs /absolute/private/hmao-config.json
# После приёма задания через прежние маршруты API:
node server-api/cli.mjs import-once /absolute/private/hmao-config.json /absolute/private/hmao-publication
# После обрыва и освобождения/истечения аренды:
node server-api/cli.mjs import-resume /absolute/private/hmao-config.json /absolute/private/hmao-publication
```

`publication-init` проверяет и публикует исходный снимок до первого импорта;
повтор уже завершённой инициализации запрещён. `import-once` обрабатывает одно
задание или возвращает `null`, если сейчас нет доступного. `import-resume`
возобновляет одну прерванную попытку и не снимает действующие блокировки.
`retry_wait` обрабатывается очередным `import-once` после минимального интервала,
пока тело задания не истекло. Автоматический поллер не устанавливается.

`writ-once`/`writ-resume` при наличии `publicationRoot` используют этот же формат
снимков и сохраняют bank-events. Старый адаптер ИЛ остаётся только для прежней
отдельной репетиции без `publicationRoot`; форматы нельзя смешивать.

## Публикация

Под штатной региональной блокировкой копируется всё `data/`, а список объявленных
путей проверяется через `ops/stage_data_files.sh --list`. В снимок входят CSV
апелляции, холодные архивы, отдельные bank-events и посторонние файлы данных.
Кандидат получает номер `UUID-попытка`. После записи и синхронизации проверяются
SHA-256 файлов, календарный индекс и квитанция применения. Только затем атомарно
заменяется `current.json`. Изменение исходного снимка останавливает публикацию.

Изолированный API отдаёт публичные картотеки и CSV по `/data/`; индекс календаря
выбирается из того же снимка. Повреждённый публичный файл даёт 503, а не пустую
картотеку или прежний успешный ответ. Входные задания, квитанции, скрытые файлы
и внутренние журналы не публикуются этим маршрутом. Прежние Pages и PWA здесь
не переключаются; это ещё не проверка доступности новой публикации юристам.

Состояние `done` допустимо после подтверждения публикации. При частичном сетевом
сбое опубликованная часть учитывается в истории попыток, оставшаяся работа
сохраняется в очереди с тем же UUID. Новая попытка использует прежний дедуп
импортёра. Возобновление одной попытки не удваивает накопленные счётчики.
Непригодный дамп получает окончательный отказ, не меняет публикацию и не
прокручивается повторно. Восстановление не забирает действующую аренду.

## Сбои и восстановление

При обрыве после применения сверяется сохранённая квитанция, затем выполняется
публикация. При обрыве после переключения `current.json` подтверждается уже
опубликованный снимок, затем обновляется журнал. Незавершённый неопубликованный
кандидат без квитанции можно пересобрать из текущего снимка. Потеря квитанции
уже опубликованного снимка требует разбора; автоматического переприменения нет.
Изменение исходной версии после подготовки также требует разбора, а не
безусловного перезаписывания новых данных.

Для резервирования нужны **вместе** SQLite, `current.json`, `snapshots/`,
`jobs/` и конфигурация; SQLite не содержит саму картотеку. Для повторения
синтетического транспорта сохраняется также `responses.json`.

1. Остановить API, исполнителей и cleanup, дождаться завершения. HTTP-fence
   сам по себе не останавливает отдельные исполнители.
2. Сделать SQLite online backup штатной командой из README и скопировать
   дерево публикации в закрытый каталог. Один файл активной SQLite без WAL
   обычным копированием не резервировать.
3. На отдельной копии задать собственные пути базы и `publicationRoot`,
   проверить принадлежность региону и чтение опубликованных JSON/CSV.
4. Запустить `import-resume`, проверить UUID, очередь, журнал и отсутствие
   повторного добавления дел. Исходную копию не заменять; locks не удалять.

Проверка 12.11.2026 выполнена на другой локальной копии и новом процессе.
Внешнее зашифрованное резервирование и восстановление на другой машине остаются
отдельной проверкой перед рабочим пилотом.

## Подтверждённые сценарии и оставшаяся граница

Сквозные тесты покрывают первоначальную публикацию, дамп первой инстанции,
апелляцию с CSV, пачки по ссылкам и по номеру, оба трека, общую операцию ИЛ,
частичный повтор и терминальный отказ. Принудительное завершение процесса
проверено после применения и после публикации. Отдельно проверены повреждённый
кандидат и публичный файл, изменение исходной базы, сохранность архивов/событий
и восстановление базы вместе с деревом снимков.

Перечисленные синтетические сценарии проверены на Mac и Linux. Дополнительно
выполнен закрытый пилот ниже. Защищённая выгрузка рабочих KV, внешнее резервирование,
прежние установленные приложения, генерация выпусков, рассылки и OCR-зависимость
GitHub/SSH остаются отдельным этапом. Переключение рабочих API в эти команды не входит.

## Закрытый пилот на VPS

Автор: Александр Селиванов. Подготовка 12.11.2026.

Режим `closed-pilot` разрешён только для ХМАО и каталога
`/srv/projects/sbersud/pilot/hmao/state/publication`. Это отдельные SQLite,
картотека и новые секреты; рабочие профили не копируются. Состояние инициализирует
`pilot_setup.py` один раз: 600 синтетических дел против банка и 200 исков банка.

API слушает `127.0.0.1:18081`, отдельная копия шлюза — `127.0.0.1:18082`.
Логическое имя шлюза проверяется прежним модулем, но транспорт закреплён на
loopback и никогда не обращается к публичному `api2`. Публичные API, DNS,
nginx, рабочие таймеры и рассылки в установку пилота не входят. Службы пилота
запускаются вручную, без включения при загрузке; импорт — отдельная разовая служба.

`court-network.json` разрешает только выбранные суды из реестра ХМАО.
Чтение ограничено HTTPS-карточками и поиском `/modules.php`, 12 запросами
на задание, проверкой сертификата и публичного IP, 10/25 секундами ожидания
соединения/ответа, 8 МиБ ответа. Каждый адрес перенаправления проверяется заново.
Для выбранного `суд--регион.sudrf.ru` допускается его точный новый адрес
`суд.регион.sudrf.ru`, на который перенаправляет сам портал.
Произвольные запросы, модели, OCR через внешнюю команду и доставка отключены.
HTTP 200 сам по себе не считается доказательством разбора карточки.

Службы `sbersud-pilot-api`, `sbersud-pilot-gateway`, `sbersud-pilot-import`
используют отдельного пользователя `sbersud-pilot`; лимит общей группы:
25% одного CPU, 320 МиБ мягкий и 384 МиБ жёсткий предел памяти, без swap.
Рабочая картотека и служебное состояние основной установки скрыты от служб.
Для API и шлюза дополнительно запрещена сеть вне loopback.

`pilot-load.mjs` проверяет работающий API: 24 синтетических профиля,
8 запросов/сек в течение 30 секунд, затем 24 запросов/сек 60 секунд,
не более 8 одновременно. Измеряются задержки и ошибки; этот тест не нагружает суды.
Фактическую установку, измерения и ограничения проверки фиксировать отдельным отчётом.

12.11.2026 установлен пакет из `c0a394f49f93b5e7dfaa13bdf074f0d4a563f7d1`.
На Linux прошли 26 тестов. Контрольная пачка прочитала две настоящие карточки
Сургутского городского суда; его настоящая поисковая выдача прошла через
отдельный шлюз. Найденное в дампе давно решённое дело помещено в архив без новости.
Очередь пуста, оба UUID завершены. Проверены повтор после сетевого отказа,
публикация по контрольной сумме, SIGKILL API и восстановление SQLite вместе
с деревом публикации; профиль и календарь сохранены.

В итоговом тесте 1680 запросов дали 0 ошибок. На 8 запросах/сек p95 — 469 мс.
При целевых 24 запросах/сек фактический темп — 16,5, p95 — 1082 мс;
заявлять выдержанные 24 запросов/сек нельзя. Генератор нагрузки работал в отдельной
службе с пределом 15% CPU; сам пилот — в `sbersudpilot.slice` с 25% CPU.
Импорт завершился во время высокой нагрузки. Обычный парсер в это время не был
активен, поэтому совместный пик с его полным обходом ещё не измерен.

После испытания API и шлюз оставлены запущенными. Автоматического опроса очереди
и запуска после перезагрузки нет. Для следующего закрытого импорта:

```sh
systemctl start sbersud-pilot-import.service
# Для незавершённого задания сначала дождаться освобождения аренды и выполнить:
runuser -u sbersud-pilot -- env TEST_PYTHON=/opt/court-monitor-runtime/venv/bin/python \
  /usr/local/bin/node /srv/projects/sbersud/pilot/hmao/current/server-api/cli.mjs import-resume \
  /srv/projects/sbersud/pilot/hmao/config/api.json /srv/projects/sbersud/pilot/hmao/state/publication
```

Секреты находятся только в закрытом `config/api.json`; не передавать их в журналы
команд. Остановить пилот можно через `systemctl stop sbersud-pilot-api.service
sbersud-pilot-gateway.service sbersud-pilot-import.service`, без остановки рабочих служб.
