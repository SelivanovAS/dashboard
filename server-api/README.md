# Серверный API: изолированный прототип

Прототип исполняет общий `cloudflare-worker/worker.js` в Node.js 24.14.1,
с отдельным процессом, неизменяемой конфигурацией и SQLite каждой территории.
Он **не является готовым выпуском для переключения рабочих API**. Режим, отличный
от `isolated`, отвергается. Установок служб, DNS, Worker/KV, таймеров и писателей
этот каталог не выполняет. ЕРКНМ и старый сервер не затрагиваются.

Внешние запросы серверного процесса запрещены. Публичные имена API используются
как проверяемый Host, сервер слушает только `127.0.0.1`. Секреты и URL с токенами
не выводятся в его журналы. Профили, подписки, роли, календарь, посещения, прогресс
и восстановление используют общий код с Worker. `RUNTIME_ENV` не переключается
между территориями: в одном процессе можно создать только один экземпляр API.

## Реализация и границы

| Часть | Реализовано | Граница |
|---|---|---|
| SQLite вместо KV | get/put/delete/list, JSON/bytes/stream, metadata, абсолютный срок, страницы, проверка региона | Нет eventual consistency и квот Cloudflare; данные видны сразу |
| Профили | Одноразовый код, смена календарного токена, конфликт base_ts, 7/30 дней и восстановление | Весь запрос, включая GET с активностью, — одна транзакция; часы watchlist монотонны |
| Подписки и админка | Роли, полные списки, labels, watchlist, удаление, сохранение публичного VAPID | Отправка push выключена; приватный VAPID не создаётся и не заменяется |
| Календарь | Прежние пути, токены, UID и часовой пояс суда; 503 при недоступном индексе | Сверен с полными данными; прежнее устройство ещё не проверено |
| Приём импортов | Тело, UUID, история и местное задание — одна транзакция; защита от повторов | Действующий поллер нельзя просто направить сюда: done без местного подтверждения запрещён |
| Дампы и пачки | Устойчивая очередь и общий runner с адаптерами, полная queue | Подключение существующих импортёров к местной публикации ещё требуется; в прототипе остаются queued |
| «ИЛ не нужен» | Настоящий mark_writ_waived.py, штатный run_lock, bank-events, кандидат и проверка его публикации | Только помеченная синтетическая копия, без Git/push/уведомлений |
| Шлюз api2 | Общий валидатор адреса, размера, SHA-256, токена и суда, проверенный через внедряемый транспорт | Сетевой транспорт на рабочий api2 не включён; обычный запуск отвергает envelope с 503 |
| admin/gh-runs | Совместимая форма ответа из местных заданий | Не подменяет журнал обычного действующего парсера |
| admin/dispatch | Прежние роли/белый список; импортные задания переиспользуют UUID | update_cases/test_digest дают 503; генерация и доставка — следующий этап |
| Обслуживание | Команда cleanup | Таймер не установлен, боевой cron не меняется |

Облачный путь общего Worker сохраняется при отсутствии серверных адаптеров.
Исправлена полная пагинация подписок, профилей и свежести импортов.
Опись `inventory.py` обходит зависимости обработчиков и все workflow-файлы;
она различает рабочие операции, OCR, диагностику и CI. Изменение перечня workflows
требует явной классификации нового файла. Опись содержит имена секретов, без значений.

## Проверка и запуск

Нужны Node.js **24.14.1**, Python **3.12**, для описи — PyYAML. Сторонних
npm-зависимостей у runtime нет. В этой версии Node встроенный SQLite отмечен
экспериментальным; версия закреплена, смена требует проверки.
Технические контракты: [Node SQLite](https://nodejs.org/download/release/v24.8.0/docs/api/sqlite.html),
[KV list](https://developers.cloudflare.com/kv/api/list-keys/) и
[KV put](https://developers.cloudflare.com/kv/api/write-key-value-pairs/).

Из корня исходной программы:

```sh
node --test server-api/tests/*.test.mjs
node server-api/benchmark.mjs /absolute/private/benchmark.json
python3 server-api/inventory.py /absolute/private/inventory.json
```

Тесты создают временные данные и локальные процессы. Штатной блокировке нужен
локальный ps, HTTP-проверке — loopback. В исходный CI добавлено отдельное задание;
его наличие не означает, что оно уже запускалось. Mac-проверка не заменяет
Linux/VPS-проверку ограничений systemd и ресурсов вместе с парсером.

Подготовить закрытый JSON с **тестовыми** OWNER_SECRET, OPERATOR_SECRET, PUSH_SECRET,
PROGRESS_SECRET — различными строками не короче 16 символов, права файла 0600.
Для каждой территории свой каталог, конфиг и порт. Конфиг создаётся новым файлом:

```sh
python3 server-api/configure.py --region hmao \
  --runtime-root /absolute/private/hmao \
  --secrets-file /absolute/private/hmao-secrets.json \
  --output /absolute/private/hmao-config.json --port 18081
node server-api/cli.mjs index /absolute/private/hmao-config.json /absolute/isolated/data
node server-api/server.mjs /absolute/private/hmao-config.json
```

Генератор читает региональный wrangler-профиль и реестр судов: API, Pages URL и
публичный VAPID остаются своими. Настоящие секреты для репетиции не подставлять.
Перед рабочим пилотом отдельно сверить наличие и совместимость прежних секретов;
не заменять их новыми ради прохождения проверки конфигурации.

Полные картотеки API не раздаёт: их будущая публикация относится к веб-серверу.
Индекс не содержит тексты актов и лишние события. Основной JSON содержит регион;
bank JSON может его не иметь, как в нынешнем формате. Построитель сверяет регион
и неизменность обоих файлов. Вызывающий процесс должен удерживать региональную
блокировку либо дать неизменяемый снимок. На один запрос API закрепляется одна
версия индекса; замена перечитывается без загрузки полной картотеки.

Шаблоны обратного прокси и службы лежат в `deployment/`. Они не установлены.
Для пилота нужны закрытый адрес, сертификат, отбрасывание неизвестных Host до
проксирования, отдельные пользователи/каталоги и подтверждённый бюджет ресурсов.
Привычные bind mounts первого этапа этот прототип не меняет.

## Очередь и восстановление

Состояния: `queued → leased → applied → published → done`. Просроченная аренда
даёт `uncertain`; поколение аренды защищает от устаревшего исполнителя.
HTTP `/import-result` не может завершить местное задание: runner сначала проверяет
применение и публикацию и затем вызывает общий обработчик журнала.

Повтор с тем же `Idempotency-Key` (8–120 символов) возвращает прежний UUID;
другое тело с этим ключом даёт 409. Для прежних форм без заголовка используется
хеш тела и роли, срок 72 часа. Намеренная повторная пачка с тем же телом в этот
срок должна получить новый ключ. Дедуп не заявляется бессрочным.

Для репетиции ИЛ нужен отдельный каталог с `.sbersud-isolated.json`:
`{"region":"hmao","synthetic":true}`, `current.json` с версией `initial` и
`snapshots/initial/data/` с шестью JSON основного/банковского трека и их событий.
Полный пример создаёт `tests/jobs.test.mjs`.

```sh
node server-api/cli.mjs writ-once /absolute/private/hmao-config.json /absolute/isolated/writ
node server-api/cli.mjs writ-resume /absolute/private/hmao-config.json /absolute/isolated/writ
```

Применение меняет частный кандидат; `current.json` переключается после проверки
хешей под штатной блокировкой. Изменение исходного снимка останавливает публикацию.
После обрыва сверяется сохранённая квитанция. Незавершённый частный кандидат ИЛ
можно пересобрать: он ещё не менял текущий снимок. Этот приём нельзя автоматически
переносить на сетевые импорты или отправку сообщений.

## Состояние и резервирование

`namespace-snapshot.mjs` собирает **весь** namespace через внедряемый адаптер
list/getWithMetadata: все страницы, включая пустую промежуточную, неизвестные
ключи, binary values, metadata и абсолютные expiration. Два полных прохода должны
совпасть. Рабочего Cloudflare-клиента здесь нет; выгрузка KV не выполнялась.
Совпадение проходов само по себе не доказывает прекращение старых писателей.

Локальный снимок SQLite содержит все ключи, включая истёкшие, местные задания
и дедупликацию. Импорт проверяет SHA-256/территорию/версию и допускается только в
пустую базу. Просроченные записи не оживают, оставшийся TTL не начинается заново.
Снимок содержит секретные токены: закрытый каталог, без приложения к отчёту/чату.

```sh
node server-api/state-tool.mjs export hmao /absolute/private/state.sqlite /absolute/private/state.snapshot.json
node server-api/state-tool.mjs restore hmao /absolute/private/restored.sqlite /absolute/private/state.snapshot.json
node server-api/state-tool.mjs check hmao /absolute/private/restored.sqlite /absolute/private/state.snapshot.json
node server-api/state-tool.mjs backup hmao /absolute/private/state.sqlite /absolute/private/backup.sqlite
```

Online backup использует SQLite backup API с проверкой целостности. Копирование
одного файла при активном WAL не используется. Внешняя зашифрованная копия и
учебное восстановление на другой машине ещё требуются до рабочего пилота.

`node server-api/cli.mjs fence CONFIG` устойчиво запрещает все HTTP-запросы,
включая GET календаря с активностью. Отдельные runner/cleanup надо остановить и
дождаться отдельно. Публичной кнопки снятия запрета нет; для новой репетиции —
новая проверенная копия. Рабочий протокол окна ещё требуется подготовить.

## Перенос и возврат рабочего пилота

1. Закрытый контрольный адрес, права, секреты, Linux, ресурсный бюджет и backup.
2. Остановить все старые писатели, в том числе GET-активность, cleanup, импорт,
   связанные GitHub-задачи. Зафиксировать завершение, а не только выключить POST.
3. Разрешённым доступом выгрузить все страницы KV; повторить и сверить проходы.
   Перенести абсолютные сроки, значения/метаданные, токены, UUID и VAPID. Права
   KV/DNS текущей сессии для этого отсутствуют; прототип их не расширяет.
4. Восстановить пустую SQLite, сверить полный снимок, связи, истечение TTL,
   очередь и прежние календарные URL. Затем `cli.mjs reconcile CONFIG` переносит
   незавершённые KV-задания в местную таблицу без нового UUID.
5. Подключить дампы/пачки к runner и местной публикации, api2 к защищённому
   транспорту. Проверить обрывы/повторы и настоящее применение на разрешённых копиях.
6. Подготовить совместимую публикацию данных и обновление прежних приложений,
   отдельную генерацию/доставку и единый журнал исходящих сообщений.
7. Только после этого согласовать рабочее переключение ХМАО: временный мост
   со старых адресов к одному новому хранилищу, затем DNS/сертификат. Два обычных
   цикла и старые установленные приложения — отдельная приёмка.

До новых записей допустим возврат маршрута к проверенному прежнему хранилищу.
После новых записей первый безопасный путь — предыдущая совместимая версия
серверной программы с **актуальной SQLite**, без отката данных.

Возврат в Cloudflare требует запрета записей, обратного экспорта актуального
состояния, применения удалений/оставшихся TTL и переноса местных журналов заданий
и защиты от повторов. Снимок содержит эти сведения, но автоматическая обратная
загрузка в рабочий KV **не реализована и не проверена**. Простой возврат DNS к
старому namespace недопустим. До пилота нужна репетиция этой процедуры либо
согласованный возврат только версии на VPS.

Существующие иконки, адреса Pages, localStorage, заметки, избранное, прочитанное
и разрешения push не меняются этим прототипом. Дополнительный `delosud.ru` и
разделы `/hmao/`, `/ural/`, `/bashkortostan/`, `/tyumen/` не публиковались.
Приёмка перенесённого исполнителя первого этапа не подменяется этими тестами.
